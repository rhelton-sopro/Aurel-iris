anotar ground truth iridológico para readings existentes, gerando o corpus de fixtures
necessário pra Wave B (PLAN 07.1-02 — P0a + P0b + B1d + B1b) e pro backlog Phase 9
(RESP-01..03 — confidence visível, calibração linguística, checklist visual).

pra B1b (recalibrar centroides LAB). Sem ground truth iridológico, B1b vira chute
informado. Mesma coleta serve tripla função (Wave B + Phase 9 backlog + Phase 10 seed
dataset). Adiar pra Fase 9 desperdiça o trabalho de Wave B.

**Por que NÃO implementar direto sem PLAN:** escopo é 8-14h, toca migration + RLS +
middleware + 5 componentes + 2 routes + server actions + tests. Atomic commits naturais.
Founder gate em duas decisões (env vs hardcoded UUID; RLS strategy).

**Workflow alvo (founder usando a página):**
1. Founder acessa /admin/calibration
2. Vê lista de leituras com vision_features, filtra por "pendente"
3. Clica numa leitura → /admin/calibration/[id]
4. Vê 6 fotos da íris lado a lado + relatório técnico bruto formatado
5. (Opcional) Clica "Copiar relatório técnico" → cola em conversa externa pra análise
6. (Opcional) Clica "Baixar fotos" → zip ou links individuais TTL 24h
7. Preenche form: cor real, constituição real, achados certos / inventados / faltantes, notas
8. Clica "Salvar anotação" → persiste em calibration_annotations
9. Volta pra lista, filtra "anotado", confere
10. (Próxima sessão) AI assistant lê todas as annotations, deriva calibração quantitativa

Purpose: tooling pra calibração colaborativa founder ↔ AI; pré-requisito pra Wave B
informada por dados; foundation pra Phase 10 dataset.
Output: página funcional protegida por founder gate, com persistência em tabela nova,
testada e committada com atomic structure.

-- supabase/migrations/0009_calibration_annotations.sql
-- Idempotent ground-truth annotation table for calibration sprint (founder ↔ AI assistant).
-- Used by /admin/calibration page (founder-only) to capture iridological ground truth
-- per reading. Corpus feeds Wave B (PLAN 07.1-02) centroid recalibration + Phase 9
-- responsible-product calibration + Phase 10 learning system seed dataset.

create extension if not exists "pgcrypto";

create table if not exists calibration_annotations (
  id uuid primary key default gen_random_uuid(),
  reading_id uuid not null references readings(id) on delete cascade,
  annotated_by uuid not null references auth.users(id) on delete restrict,
  annotated_at timestamptz not null default now(),

  real_iris_color text not null,
  real_constitution text not null,
  findings_correct text default '',
  findings_invented text default '',
  findings_missed text default '',
  notes text default '',

  reviewed boolean not null default false,
  reviewed_at timestamptz
);

-- One annotation per reading. Updates overwrite via UPSERT in server action.
do $$
begin
  if not exists (
    select 1 from pg_constraint where conname = 'calibration_annotations_reading_id_key'
  ) then
    alter table calibration_annotations
      add constraint calibration_annotations_reading_id_key unique (reading_id);
  end if;
end $$;

-- Enum check constraints (mirror P0a future enum + escolas iridológicas brasileiras).
do $$
begin
  if not exists (
    select 1 from pg_constraint where conname = 'calibration_annotations_iris_color_check'
  ) then
    alter table calibration_annotations
      add constraint calibration_annotations_iris_color_check
      check (real_iris_color in ('azul','verde','castanho','mista_biliar','mista_hematogenea','outra'));
  end if;
  if not exists (
    select 1 from pg_constraint where conname = 'calibration_annotations_constitution_check'

    alter table calibration_annotations
      add constraint calibration_annotations_constitution_check
      check (real_constitution in ('linfatica','biliar','hematogenea','mista_biliar','mista_hematogenea','neurogenica'));
  end if;
end $$;

create index if not exists calibration_annotations_reviewed_idx on calibration_annotations(reviewed);
create index if not exists calibration_annotations_annotated_at_idx on calibration_annotations(annotated_at desc);

alter table calibration_annotations enable row level security;

```ts
// app/actions/calibration.ts
'use server'
import { createClient } from '@/lib/supabase/server'
import { isFounderEmail } from '@/lib/auth/founder'
import { revalidatePath } from 'next/cache'
import { z } from 'zod'

const annotationSchema = z.object({
  reading_id: z.string().uuid(),
  real_iris_color: z.enum(['azul','verde','castanho','mista_biliar','mista_hematogenea','outra']),
  real_constitution: z.enum(['linfatica','biliar','hematogenea','mista_biliar','mista_hematogenea','neurogenica']),
  findings_correct: z.string().default(''),
  findings_invented: z.string().default(''),
  findings_missed: z.string().default(''),
  notes: z.string().default(''),
})

export async function saveAnnotation(input: z.input<typeof annotationSchema>) {
  const supabase = await createClient()
  const { data: { user } } = await supabase.auth.getUser()
  if (!isFounderEmail(user?.email)) {
    return { error: 'Forbidden' }
  }
  const parsed = annotationSchema.safeParse(input)
  if (!parsed.success) return { error: 'Invalid input', issues: parsed.error.issues }

  // UPSERT: if annotation exists for this reading, update; else insert.
  const { error } = await supabase
    .from('calibration_annotations')
    .upsert(
      { ...parsed.data, annotated_by: user!.id, annotated_at: new Date().toISOString(), reviewed: false },
      { onConflict: 'reading_id' }
    )
  if (error) return { error: error.message }

  revalidatePath(`/admin/calibration/${parsed.data.reading_id}`)
  revalidatePath('/admin/calibration')
  return { ok: true }
}

export async function markReviewed(readingId: string) {
  const supabase = await createClient()
  const { data: { user } } = await supabase.auth.getUser()
  if (!isFounderEmail(user?.email)) return { error: 'Forbidden' }
  const { error } = await supabase
    .from('calibration_annotations')
    .update({ reviewed: true, reviewed_at: new Date().toISOString() })
    .eq('reading_id', readingId)
  if (error) return { error: error.message }
  revalidatePath(`/admin/calibration/${readingId}`)
  revalidatePath('/admin/calibration')
  return { ok: true }
}
```

<failure_modes>
- **FOUNDER_EMAIL env not set in production:** `isFounderEmail` fail-closed (returns false for everyone) — middleware blocks /admin/* universally. Acceptance: documented in .env.example + onboarding runbook. Founder responsibility to set in Vercel env.
- **RLS bypass via service-role accidentally exposing annotations:** mitigated by NOT using service-role client for any annotation-related query. Service-role only used for (a) reading + reading_images SELECT in the detail route (because therapist_id RLS would block founder), and (b) signed URL generation. Annotations always pass through user client + RLS.
- **Race condition on UPSERT during concurrent founder edits:** UNIQUE constraint on reading_id forces serialization at DB level. Last-write-wins (overwrites). Acceptable — only one founder.
- **Photo download zip blows up Vercel function memory (4.5MB limit on Pro plan):** 6 photos × ~2-3 MB each = ~12-18 MB raw. Zip is Vercel function memory issue. Mitigation: switch to "JSON of signed URLs" for download (browser fetches each separately) if zip OOMs. Decision in Wave 4 task 6 — start with JSON option (simpler, no memory risk).
- **Founder accidentally annotates wrong leitura:** form has reading_id in URL + reading visual context. UPSERT with onConflict prevents duplicate rows but allows OVERWRITE. Mitigation: optionally show "previous annotation" diff before save. Defer to follow-up if needed.
- **Migration 0009 has FK to auth.users that doesn't exist on a fresh dev DB:** auth schema is auto-created by Supabase. Acceptable — local dev with `supabase start` includes auth schema.
- **Founder email change in future:** changing FOUNDER_EMAIL env var rotates founder identity. Old annotations remain attributed to old user UUID via annotated_by FK. Acceptable historic record.
- **Storage signed URL TTL=600s expires while founder is annotating slowly:** signed URLs in detail page are server-rendered at request time. If founder takes >10min on form, photos may break on accidental refresh. Mitigation: page revalidate every 10min OR generate fresh URLs on render. Defer if not observed in practice.
