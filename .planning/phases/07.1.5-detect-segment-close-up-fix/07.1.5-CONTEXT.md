# Phase 07.1.5: Detect/Segment Robustness for Close-up Iris Photos — Context

**Gathered:** 2026-05-11
**Status:** Ready for planning

<domain>
## Phase Boundary

Make `pipeline.detect.find_iris` + `pipeline.segment.iris_mask` produce **geometrically consistent iris circles** across the 3 angles (frontal/lateral/backlight) of the same eye in close-up iris photos (where MediaPipe FaceLandmarker returns `no_face` because there's no facial context). Convergence gate: segment centers ≤50 px apart AND segment radii within ±15% variance for the 3 angles of one eye. Downstream feature verification (classify_iris_color, _classify_constitution converging on Nailli) is **out of scope** — that's Phase 07.2's job (Wave C corpus + threshold tuning over clean inputs).

Capture UX unchanged (Option E from DISCUSSION-NOTES rejected). Existing reading auto-re-segmentation NOT in scope (ondemand reprocess only).

</domain>

<decisions>
## Implementation Decisions

### Approach: B → C cascade (color pre-seg first, U-Net CASIA fallback)
- **D-01:** Approach **B (color-based pre-segmentation before Hough)** is the primary implementation. Convert image to HSV or LAB, build a binary mask filtering iris-saturated pixels (sclera is desaturated; eyelid/skin distinct), apply morph ops (erode/dilate), then run Hough on the masked image so the accumulator can't pick up eyelid/eyebrow circles.
- **D-02:** Approach **C (U-Net pre-trained on CASIA-Iris)** is the fallback if B fails verification. Modal image already has `torch==2.11.0` baked (Phase 5 RESEARCH reserved for v1.1 path); C requires model selection + pre-bake in image via `run_commands wget` + inference path in detect.py.
- **D-03:** Approaches A (Hough tuning), D (Haar cascade), F (SAM/U²-Net/etc) are **deferred unless B+C both fail**. A is incremental tuning unlikely to fix the root cause (Hough fundamentally struggles with cílios/specular in close-ups). D adds a dep without a clear win over B. F is heavier than C.

### Verification gate
- **D-04:** B is declared **passed** when: **Nailli + 2-3 synthetic close-up fixtures** (sourced from other existing readings in the DB, not Nailli; founder's iridology readings are inherently close-up so no synthetic cropping needed) all show segment centers ≤50 px apart AND segment radii within ±15% across 3 angles of same eye.
- **D-05:** Synthetic fixture selection: planner picks 2-3 readings from `readings` table with `status='ready'` AND `client_id != Nailli` AND has 6 images (3 angles × 2 eyes). Local probe runs them; convergence table per fixture is the PR evidence.
- **D-06:** Modal redeploy + Nailli reprocess is the **integration gate** at the END of P2 (after local convergence). Modal redeploy stays founder-gated per phase 7.2 cross-cutting constraint pattern.

### Plan structure
- **D-07:** **2 plans**:
  - **P1** — B implementation + local probe loop + synthetic fixture iteration + local convergence gate. Stop-loss criterion: if 2-3 internal iterations don't show convergence trajectory (segment center spread shrinking toward target), declare B infeasible and recommend C escalation in P1 SUMMARY (no Rule 4 needed; clean handoff to P2).
  - **P2** — Modal redeploy + Nailli reprocess + detect_diagnostics gate + final synthetic fixture cycle. If P1 declared B infeasible, P2 morphs into C research-phase + implementation. If P1 declared B passing, P2 just integrates + verifies.
- **D-08:** P1 produces PR evidence: per-fixture detect_diagnostics table (segment center spread, radius variance) + enhanced_polar PNG showing visible iris texture filling polar width.
- **D-09:** P2 produces final PR evidence: Nailli `processing_metadata.detect_diagnostics` from production Modal reprocess + side-by-side comparison with pre-fix baseline (commit `8494a4a` Modal call `fc-01KRBPC40B4D15XGQJPSNMNX6V`).

### Out-of-scope (explicit boundaries)

- **D-11:** Existing readings (other clients) NOT auto-re-segmented when Modal redeploys; founder can ondemand-reprocess any reading. No batch backfill script.
- **D-12:** Downstream feature convergence on Nailli (classify_iris_color → verde-mosaico, constitution → mista_biliar, sectoral_pigments non-empty) is **explicit non-goal** for 07.1.5. That's Phase 07.2's gate after corpus + threshold tuning over clean inputs.

Empirical baseline (call_id `fc-01KRBPC40B4D15XGQJPSNMNX6V`, commit `8494a4a`):

|---|---|---|---|---|

**Center spreads to beat:** right 700 px → target ≤50 px (14× tighter). Left 1497 px → target ≤50 px (30× tighter).
**Radius variance to beat:** right 131/112/191 = 1.7× variance → target ±15% (0.85-1.15× variance).

**Visual baseline PNGs** to compare post-fix vs pre-fix:
- `vision-service/scripts/output/71a7bf1d-747f-4de8-9129-13b69197c6a4_right_enhanced_polar.png`
- `vision-service/scripts/output/71a7bf1d-747f-4de8-9129-13b69197c6a4_left_enhanced_polar.png`

The right-eye PNG visually shows ~35% iris texture + ~65% pálpebra/esclera/skin — post-fix should be ~100% iris texture across polar width.

**Color-based pre-seg principle (Approach B):** sclera saturation (HSV) typically < 0.10; iris saturation typically > 0.15 even when "azul claro"; skin/eyelid is brownish but with low local texture variance vs iris's striated radial pattern. Mask candidate pixels first, then HoughCircles on the masked image dramatically constrains the accumulator's search space.

**U-Net CASIA-Iris (Approach C) — research starting points:**
- CASIA-IrisV4 dataset (open, ~50k images, pixel-level masks)
- Public pre-trained checkpoints: `IrisParseNet`, `OpenEDS-Iris-Segmentation`, `iris-segmentation-pytorch` (GitHub)
- Model size target: ≤200MB (Modal image cold-start envelope)
- Inference target: ≤200ms per image on T4 (6 images × 200ms = 1.2s overhead; fits 120s function timeout)
