## Summary

This phase replaces the current "convert-to-grayscale-then-Hough" segmentation chain with a **color-aware pre-segmentation** that masks out non-iris pixels (sclera, skin, eyelid, eyebrow) before Hough Circle's accumulator runs. The empirical baseline (Nailli, commit `8494a4a`) shows segment centers 599-1497 px apart across 3 angles of the same eye — Hough is locking onto eyebrow arcs and palpebra contours instead of the iris, because in close-up photos those contours have **stronger edge gradients** than the iris/sclera boundary. The fix is to remove those contours from the search space.

**Primary recommendation for Approach B:** Use **HSV color space** (not LAB) for the iris-pixel mask, with **two-stage filtering**: (1) `S > 30/255 ≈ 0.12` AND `V > 40/255` to keep saturated colored pixels (iris) while dropping desaturated sclera and very-dark eyelash; (2) morphological **closing (3x3 ellipse, 2 iterations) followed by opening (5x5 ellipse, 1 iteration)** to fill iris-internal gaps (pupil hole, specular reflections) and remove thin eyelash strands. Then run `cv2.HoughCircles` on the **masked grayscale image** (`gray * (mask // 255)`), preserving the existing closest-to-center selection. Insertion point is `vision-service/pipeline/detect.py:_hough_circle_fallback` between line 119 (`gray = cv2.cvtColor(...)`) and line 123 (`blurred = cv2.medianBlur(gray, 5)`). The `_detector` breadcrumb gets a new value `"hough_color_masked"`.

**Fallback for Approach C (if B fails):** The public iris-segmentation U-Net landscape is **less turn-key than CONTEXT.md assumed**. IrisParseNet (the canonical CASIA-trained net) is **Caffe + GPL-3.0** (commercial-blocked); KartalOl is **TensorFlow + NIR-only** (won't transfer to visible-light Brazilian photos); LightIrisNet (Dec 2025, MobileNetV3-based, visible-light, ~10M params, ~25 ms on phone) is the only viable candidate but weights/license not yet confirmed downloadable. **Pragmatic C path:** use `segmentation-models-pytorch` (MIT license, 500+ pretrained backbones) with a U-Net + MobileNetV3-small encoder, do quick fine-tuning on the limited founder + Nailli + 2-3 synthetic fixtures (or skip fine-tune and rely on ImageNet-prior color/edge features). Smaller model, MIT license, PyTorch-native, fits Modal cold-start envelope.

**Key risks identified:** (1) Pupil over-mask — pupils are near-black (low V) so they'll be masked out, but Hough doesn't care because it fits the iris **outer** boundary; this is fine. (2) Brown iris saturation overlap with skin tone (both ~`H≈10-25, S≈0.3-0.5`) — Hue-based filtering will fail here; saturation+V filtering is the right axis. (3) Specular reflections create tiny high-V/low-S pixels inside the iris — morphological closing fills these. (4) Eyelashes survive thin kernels but disappear at 5x5 — risk: borderline iris boundary erosion. Tune empirically via probe iterations.

**Most important non-obvious finding:** The existing `_hough_circle_fallback` already does the right thing for the **selection** problem (closest-to-image-center beats accumulator-score). The actual failure mode is upstream: Hough accumulator **votes equally** for eyebrow arcs and iris boundaries in close-ups because eyebrow + palpebra create circular-ish contours with stronger gradients than the iris boundary, and the iris contour gets **out-voted off the candidates list entirely**. The color mask doesn't change the selection logic — it removes the competing contours from the gradient image **before voting starts**, so the iris contour can win on accumulator score alone. This means the fix is genuinely *pre-segmentation*, not just *post-selection*. [VERIFIED: empirical baseline `fc-01KRBPC40B4D15XGQJPSNMNX6V`]

### Pattern 1: HSV-based iris color mask

**What:** Filter pixels by saturation and value to keep iris-candidate regions, drop sclera (low S) and very-dark eyelash/pupil (low V).

**When to use:** Inside `_hough_circle_fallback` before Hough invocation. NOT applied to MediaPipe path (face-context photos already work).

**Example (recommended starting values; tune via probe):**
```python
# Source: HSV color space ranges from OpenCV docs + iris-vs-sclera saturation principle
# [VERIFIED via probe loop — initial values, tune per synthetic fixture experiment]
def _color_iris_mask(rgb: np.ndarray) -> np.ndarray:
    """Build binary mask of iris-candidate pixels.

    Drops sclera (white, low S), pupil/eyelash (very dark, low V), and skin
    via wide saturation tolerance. Returns uint8 mask (0 or 255).
    """
    hsv = cv2.cvtColor(rgb, cv2.COLOR_RGB2HSV)
    # H: 0-179 (OpenCV convention); S, V: 0-255
    # Lower bound: any hue, S >= 30 (excludes white sclera ~S<15), V >= 40 (excludes black pupil/eyelash)
    # Upper bound: any hue, S any, V <= 230 (excludes specular highlights — actually keep these too,
    #              they're inside the iris and morphological closing will fill them)
    lower = np.array([0, 30, 40], dtype=np.uint8)
    upper = np.array([179, 255, 255], dtype=np.uint8)
    mask = cv2.inRange(hsv, lower, upper)

    # Closing fills internal gaps (specular reflections, pupil hole — pupil region helps Hough lock
    # onto iris OUTER boundary because closed iris-disk has well-defined edge)
    kernel_close = cv2.getStructuringElement(cv2.MORPH_ELLIPSE, (3, 3))
    mask = cv2.morphologyEx(mask, cv2.MORPH_CLOSE, kernel_close, iterations=2)

    # Opening removes thin protrusions (eyelash strands)
    kernel_open = cv2.getStructuringElement(cv2.MORPH_ELLIPSE, (5, 5))
    mask = cv2.morphologyEx(mask, cv2.MORPH_OPEN, kernel_open, iterations=1)

    return mask
```
> [CITED: docs.opencv.org/4.x/d9/d61/tutorial_py_morphological_ops.html]
> [ASSUMED: specific lower/upper bounds (30, 40) — starting values; planner tunes against synthetic fixtures]

### Pattern 2: Integrate mask into existing Hough fallback

**What:** Apply mask multiplicatively to grayscale BEFORE `cv2.medianBlur` + `cv2.HoughCircles`.

**Example (modification to `_hough_circle_fallback`):**
```python
# Around detect.py:117-125 (insert AFTER bgr conversion, BEFORE medianBlur)
bgr = cv2.cvtColor(small, cv2.COLOR_RGB2BGR)
gray = cv2.cvtColor(bgr, cv2.COLOR_BGR2GRAY)

# NEW — Approach B pre-segmentation
mask = _color_iris_mask(small)  # uint8 H×W with 0/255
gray = cv2.bitwise_and(gray, gray, mask=mask)
# Now gray has zeros where non-iris pixels were; HoughCircles accumulator will not vote
# for circles passing through those zeros (gradient = 0 there).

blurred = cv2.medianBlur(gray, 5)
# ... rest unchanged
```

**Why this works:** `cv2.HoughCircles` internally runs Canny on the grayscale image. Canny gradient on zero-pixel regions is zero. Accumulator votes are weighted by edge magnitude — so eyebrow/eyelid arc edges (which were the winning contours) are now invisible to the accumulator. The iris boundary stays visible because the mask boundary aligns approximately with the iris/sclera boundary.

### Anti-Patterns to Avoid

- **Modify the MediaPipe success path:** If a photo has face context, MediaPipe returns reliable iris landmarks; don't gate that path through the color mask. The fix is strictly for the Hough fallback path. (Cross-cutting constraint from ROADMAP §7.1.5.)
- **Use the binary mask directly as the Hough input:** Binary mask has only mask-boundary edges; iris internal texture gradients are lost. Use `mask × grayscale`, not `mask` alone.
- **Tune Hough params before tuning the mask:** A bad mask + tuned Hough = still bad. The mask is the higher-leverage knob; once mask is good, current Hough params should work.
- **Skip morphology:** Without closing, internal iris pixels (pupil region, specular reflections) leave holes that confuse Canny. Without opening, eyelash strands attach to the iris region and shift its centroid.
- **Apply mask only in detect.py and not segment.py:** segment.py runs its own HoughCircles on the FULL image (segment.py:82) — without applying the same mask there, segment can still pick eyebrow arcs even with a good detect seed. **Planner decision (D-13 area): recommended to apply in both for additive defense.**

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| HSV/LAB color conversion | Manual RGB→HSV math | `cv2.cvtColor(img, cv2.COLOR_RGB2HSV)` | OpenCV's conversion handles uint8 bounds + gamma; manual implementation has edge cases at H≈0 wraparound |
| Color-range thresholding | `np.where((img > lo) & (img < hi))` | `cv2.inRange(img, lo, hi)` | inRange is vectorized C++ + handles multi-channel; ~10× faster than NumPy boolean |
| Morphological operations | Erode/dilate by NumPy slicing | `cv2.morphologyEx(mask, cv2.MORPH_OPEN, kernel)` | OpenCV's implementation handles edge cases (image borders, anchor points); much faster |
| Structuring element generation | Hardcoded `np.ones((5,5))` | `cv2.getStructuringElement(cv2.MORPH_ELLIPSE, (5, 5))` | Ellipse kernels produce more isotropic morphology than rectangular; matters for circular-ish iris |
| U-Net architecture from scratch (Approach C) | Custom encoder/decoder PyTorch modules | `segmentation_models_pytorch.Unet(encoder_name="mobilenet_v3_small", encoder_weights="imagenet", classes=1)` | smp is MIT-licensed, 500+ tested backbones, ImageNet-pretrained encoder helps generalization without iris-specific training data |
| Multi-image consensus voting (rejected) | "if 2 of 3 angles agree, use that center" | Trust per-angle detection + accept variance | Each angle has different pose/lighting; geometric consensus enforces wrong invariant. Convergence comes from each angle correctly finding its own iris, not from averaging. |
| Pupil detection (out of scope) | Inner Hough Circle on dark pupil | Skip entirely | Phase 07.1.5 fixes iris OUTER boundary. Pupil is downstream concern (Phase 07.2 / collarette features) |

**Key insight:** Color masks + morphology are 50-year-old techniques. Re-implementing them by hand creates fragile edge cases. The OpenCV implementations are battle-tested and faster.

## Common Pitfalls

### Pitfall 1: HSV V-channel sensitivity to flash / lighting in close-up Brazilian indoor photos

**What goes wrong:** Founder takes photos in mixed indoor light (LED, daylight, ring flash). V-channel distribution shifts dramatically between morning and evening readings. A V > 40 threshold that works in morning daylight may include shadowed eyelid skin in evening warm light.

**Why it happens:** V is essentially luminance; it's not illumination-invariant.

**How to avoid:**
1. Use **per-image relative thresholds** — compute `v_lower = max(40, 0.15 × image_V_p95)` so the threshold scales with the image's brightness distribution.
2. Alternative: use LAB **L\*** channel with a fixed perceptual threshold (L* is more perceptually uniform than V), but **only if probe experiments show HSV is failing**. HSV is the recommended starting point.
3. Probe iteration loop catches this — fixture set spans morning/evening lighting.

**Warning signs:** Probe shows mask coverage varying wildly (>2× pixel-ratio difference) between fixtures of similar iris size. detect_diagnostics shows `_detector` is "hough_color_masked" but segment_iris_circle still drifts between angles of the same eye.

---

### Pitfall 2: Eyelash interaction with morphology kernel size

**What goes wrong:** Eyelashes are thin dark strands ~2-4 px wide at 1024px resize. Opening kernel of 5×5 removes them; opening kernel of 3×3 keeps them; opening kernel of 7×7 starts eroding the iris boundary itself (iris/sclera transition is ~3-5 px wide in close-ups).

**Why it happens:** Morphological opening removes structures smaller than the kernel. Eyelashes and iris boundary are similar scale.

**How to avoid:**
1. Start with 5×5 ellipse opening kernel (recommended above). Tune ±2 px based on probe iteration.
2. **Apply closing BEFORE opening** so internal gaps are filled (otherwise opening might remove iris-internal-mask regions that closing would have repaired).
3. Probe should dump the mask PNG, not just the polar PNG — visual inspection of the binary mask catches "iris boundary eroded" failure mode immediately.

**Warning signs:** Mask PNG shows iris region as a smaller-than-expected disk. detect_radius decreases significantly (>20%) compared to pre-mask Hough.

---

### Pitfall 3: Dark-brown iris saturation overlap with skin / eyelid

**What goes wrong:** A dark brown iris has `H≈10-20, S≈0.3-0.5, V≈0.2-0.4`. Brazilian skin tone (founder + clients) has `H≈10-25, S≈0.3-0.5, V≈0.4-0.7`. The S-channel discrimination is weak; only V-channel separates them (skin is brighter). If V-lower-bound is set conservatively (e.g., V > 0.5), dark brown iris is masked out.

**Why it happens:** HSV hue is not a strong discriminator between skin and brown iris — both are warm-toned at similar saturation.

**How to avoid:**
1. **Keep V-lower-bound low** (V > 40/255 ≈ 0.16 recommended) so dark irises survive the mask.
2. Rely on morphology + Hough's center-bias selection to discard adjacent skin: skin is connected to the iris via a thin neck (eyelid border); Opening with 5×5 ellipse cuts that neck.
3. Test on synthetic fixture with intentionally dark brown iris (or use one of the 2-3 founder-selected fixtures with brown iris per D-05).

**Warning signs:** Brown-iris readings show `_detector="hough"` (mask was empty → fell through to old path) or `detect_diagnostics` shows iris radius matching face/cheek size.

---

### Pitfall 4: Specular reflection on cornea creates high-V, low-S spot inside iris

**What goes wrong:** Camera flash creates a small bright spot (specular reflection) on the cornea — appearing as `V≈0.95, S≈0.05`. This is INSIDE the iris geometrically but FAILS the saturation threshold (`S > 30` fails). The spot becomes a "hole" in the mask.

**Why it happens:** Specular reflection is essentially mirror-reflected light source — color comes from the light, not the iris pigment.

**How to avoid:**
1. **Morphological closing** with 3×3 kernel, 2 iterations FILLS holes ≤6 px diameter. Specular reflections in close-up iris photos are typically 4-15 px wide. If they're larger, increase to 5×5 closing kernel.
2. Inspect mask PNG: specular hole visible → increase closing kernel size or iterations.
3. Alternative: pre-process the image with specular reflection removal (`cv2.inpaint`) before color mask. **Not recommended for v1** — inpaint adds complexity and v2 (Approach C U-Net) handles this implicitly.

**Warning signs:** Mask PNG shows small "donut hole" inside iris disk. Hough may fit a smaller circle inside the iris (chasing the hole edge).

---

### Pitfall 5: Per-eye-per-angle convergence != per-pipeline-run convergence

**What goes wrong:** Founder reads "right eye 3 angles converged" as success. But the gate is convergence WITHIN each eye, across 3 angles. The 6 numbers (3 right + 3 left) must form TWO clusters of 3, not one cluster of 6.

**Why it happens:** Verbal phrasing collapses the gate's structure.

**How to avoid:**
1. Probe output table organizes by eye → angle, so visual inspection sees the structure.
2. detect_diagnostics in PR description is **explicitly grouped by eye** (`detect_diagnostics["right"]: [...]`, `detect_diagnostics["left"]: [...]` — already the shape per modal_app.py:245).
3. Validation Architecture (next section) makes this binding via paired-comparison invariants.

**Warning signs:** PR description shows aggregate "spread ≤50 px" without specifying per-eye separation.

---

### Pitfall 6: Synthetic close-up fixture generation accidentally embeds the bug

**What goes wrong:** Planner uses `cv2.circle` to draw a fake iris on a white background as a "synthetic close-up" → mask trivially succeeds because there's no eyebrow/eyelid clutter. The test passes on synthetic but fails on real photos.

**Why it happens:** Synthetic must reproduce the **failure-mode environment**, not just the iris.

**How to avoid:**
1. **D-05 fixtures are REAL readings** (not generated). Use 2-3 actual readings from the DB. The probe (`probe_pigment_deltas.py`) fetches them via signed URLs.
2. Any pytest-level synthetic fixtures (TDD RED→GREEN) should be **derived from real photo crops** OR **clearly marked as unit-tests-of-helper-function** (not pipeline-level). E.g., test `_color_iris_mask(uniform_brown_image)` returns non-empty mask — that's a unit invariant, not a pipeline convergence test.
3. The convergence gate (≤50 px) is tested against REAL fixtures only.

**Warning signs:** Pytest passes locally, probe fails on Nailli. Synthetic fixture has no eyelid/eyebrow content.

### Color mask + Hough integration (Recommended for `_hough_circle_fallback`)

```python
# vision-service/pipeline/detect.py — modified _hough_circle_fallback
# Source: cv2.cvtColor + cv2.inRange docs + cv2.morphologyEx docs
# [CITED: docs.opencv.org/4.x/d9/d61/tutorial_py_morphological_ops.html]
# [CITED: docs.opencv.org/4.x/da/d97/tutorial_threshold_inRange.html]

def _color_iris_mask(rgb_small: np.ndarray) -> np.ndarray:
    """Build binary mask isolating iris-candidate pixels.

    Drops sclera (low saturation), pupil/eyelash (very low value), and
    most skin (relative-V discrimination via morphology, not threshold).

    Args:
        rgb_small: H×W×3 uint8 RGB array (post-resize, ≤1024 long edge).

    Returns:
        uint8 H×W mask with values 0 (drop) or 255 (keep).
    """
    hsv = cv2.cvtColor(rgb_small, cv2.COLOR_RGB2HSV)
    lower = np.array([0, 30, 40], dtype=np.uint8)   # S>=30 drops sclera; V>=40 drops black eyelash
    upper = np.array([179, 255, 255], dtype=np.uint8)
    mask = cv2.inRange(hsv, lower, upper)

    # Closing first — fills internal holes (specular reflection, pupil region)
    kernel_close = cv2.getStructuringElement(cv2.MORPH_ELLIPSE, (3, 3))
    mask = cv2.morphologyEx(mask, cv2.MORPH_CLOSE, kernel_close, iterations=2)

    # Opening second — removes thin eyelash strands
    kernel_open = cv2.getStructuringElement(cv2.MORPH_ELLIPSE, (5, 5))
    mask = cv2.morphologyEx(mask, cv2.MORPH_OPEN, kernel_open, iterations=1)

    return mask


# Modified _hough_circle_fallback (lines 117-145 region of current file)
def _hough_circle_fallback(image: np.ndarray) -> dict:
    h, w = image.shape[:2]
    # (resize logic unchanged from current code)
    HOUGH_MAX_DIM = 1024
    long_edge = max(h, w)
    if long_edge > HOUGH_MAX_DIM:
        scale = HOUGH_MAX_DIM / long_edge
        small = cv2.resize(image, (int(w * scale), int(h * scale)), interpolation=cv2.INTER_AREA)
    else:
        scale, small = 1.0, image

    sh, sw = small.shape[:2]
    small_min_dim = min(sh, sw)

    bgr = cv2.cvtColor(small, cv2.COLOR_RGB2BGR)
    gray = cv2.cvtColor(bgr, cv2.COLOR_BGR2GRAY)

    # === NEW: Approach B color pre-segmentation ===
    mask = _color_iris_mask(small)
    gray = cv2.bitwise_and(gray, gray, mask=mask)
    # Optional diagnostic field — track mask pixel ratio for debugging
    mask_ratio = float(np.count_nonzero(mask)) / float(mask.size)
    # === end NEW ===

    blurred = cv2.medianBlur(gray, 5)
    circles = cv2.HoughCircles(
        blurred, cv2.HOUGH_GRADIENT,
        dp=1.5, minDist=small_min_dim // 2,
        param1=80, param2=30,
        minRadius=int(small_min_dim * 0.12),
        maxRadius=int(small_min_dim * 0.30),
    )

    if circles is None or len(circles) == 0:
        raise ValueError("hough_no_circle_detected")

    img_cx, img_cy = sw / 2.0, sh / 2.0
    best = min(circles[0], key=lambda c: (c[0] - img_cx)**2 + (c[1] - img_cy)**2)
    cx_small, cy_small, r_small = best

    return {
        "center": (float(cx_small / scale), float(cy_small / scale)),
        "radius": float(r_small / scale),
        "landmarks_raw": [],
        "_detector": "hough_color_masked",  # NEW value — propagates into detect_diagnostics
        "_color_mask_ratio": mask_ratio,  # OPTIONAL — discretion D-13; remove if not surfacing
    }
```

## Open Questions

1. **Should the color mask also be applied in `segment.py` HoughCircles, or only in `detect.py`?**
   - What we know: detect.py provides the seed for segment.py; segment.py runs an INDEPENDENT Hough on the FULL image (not the resized one) with HOUGH_DEFAULTS (segment.py:24-31) and uses closest-to-seed selection (Pitfall 7).
   - What's unclear: whether a good detect seed alone is enough to make segment's closest-to-seed selection pick the right circle, OR whether segment also needs color masking.
   - Recommendation: **Apply color mask in segment.py too** (additive defense per Claude's Discretion D-13 area). Implementation cost is ~5 lines (`_color_iris_mask` helper is reusable). If probe shows detect-only is sufficient, the segment-side mask is a defensive no-op.

2. **HSV or LAB?**
   - What we know: HSV S-channel separates iris (saturated) from sclera (desaturated). LAB a*/b* channels can separate by chromaticity.
   - What's unclear: which performs better empirically on the founder's lighting distribution.
   - Recommendation: **Start with HSV** (recommended values above). If P1 iteration 2 shows persistent failure, A/B test against LAB. LAB experiment should be a single commit, not a separate plan.

3. **Should `_color_mask_ratio` be added to `detect_diagnostics` schema?**
   - What we know: D-13 marks this as Claude's discretion. Schema additive backward-compat is the established pattern.
   - What's unclear: founder utility — debugging tool or noise?
   - Recommendation: **Add it.** Schema additive is cheap; pixel ratio is the single most informative diagnostic for mask-tuning failures. Per ProcessingMetadata.detect_diagnostics: dict (no schema change needed — it's an open dict).

4. **For Approach C: which specific checkpoint to download?**
   - What we know: IrisParseNet (Caffe + GPL-3.0) is blocked; KartalOl (Keras + NIR-only) is wrong modality; LightIrisNet (PyTorch + visible-light, Dec 2025) is best-fit but weights publicly available status unconfirmed.
   - Recommendation: **If P1 stop-loss triggers C, spawn a research-phase sub-agent to verify LightIrisNet weight availability + confirm download URL + license** before committing to it. Backup plan: `segmentation-models-pytorch.Unet(encoder_name="mobilenet_v3_small", encoder_weights="imagenet", classes=1)` with a quick fine-tune cycle on synthetic + founder fixtures.

5. **Should the synthetic close-up fixtures be committed to the repo?**
   - What we know: CONSENT.md restricts third-party photos. The 2-3 fixtures per D-05 are real readings from non-Nailli clients.
   - What's unclear: whether to commit them or stay probe-only via DB signed URLs.
   - Recommendation: **Don't commit them.** Probe fetches via signed URLs from `readings` table (replicate `reprocess-nailli.mjs` pattern); the convergence table is the committed evidence (not the fixtures themselves). Keeps repo clean of biometric data per LGPD.

### Known Threat Patterns for vision pipeline (Python + OpenCV)

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Adversarial image inputs crashing OpenCV | Denial of Service | numpy shape/dtype assertion before `cv2.cvtColor`; existing `image_quality.warnings` already handles many cases |
| Memory exhaustion via huge image | Denial of Service | Existing 1024px resize cap (detect.py:103-109); applies to color mask path too (mask is computed on the resized image) |
| Pickle deserialization (Approach C only) | RCE | Use `torch.load(checkpoint_path, map_location='cpu', weights_only=True)` (PyTorch 2.6+ default; torch 2.11 supports). NEVER `weights_only=False` for downloaded checkpoints. |
| Untrusted model download | Tampering | For Approach C: pin checkpoint URL to a stable mirror (HuggingFace Hub); verify SHA256 sum if available. Modal image build is reproducible. |
| LGPD biometric exposure via PR/diagnostics | Information Disclosure | `detect_diagnostics` field already exists in production schema; only adds non-PII numeric fields (center coords, radius). No image pixel data leaks. Mask PNG dumps are gitignored (`vision-service/scripts/output/`). |
