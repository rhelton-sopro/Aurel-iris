## Decisions Made

- **D-05 reuse Plan 04 endpoint:** button POSTa exatamente `/api/capture/canonicalize` com `{ readingId }` — mesmo path que finalizeReadingAction chama (Plan 05). Zero duplicação de logic, idempotent path já validated. Endpoint handles auth + ownership (`.eq('therapist_id', user.id)`) — assume admin == therapist owner da leitura (founder dogfooding pattern); cross-tenant readingId → 404 capturado pelo branch `!res.ok` do button.
- **Confirm() obrigatório no button:** founder action é costly (~US\$ 0.05 + ~5s wall-clock) e idempotent — `window.confirm('Re-canonicalizar todas as 6 fotos? Custo Sonnet ~US\$ 0,05 e leva ~5s.')` evita trigger acidental em mouse hover/double-click. Plan explicitly recommended em Task 1 action notes: "NÃO esconda o confirm() — founder action é costly".
- **Toast differentiation por status_summary:** `disabled > 0` → toast.warning com "(kill-switch ativo)" suffix (D-04 surface — `CANONICAL_CAPTURE_ENABLED=false` em produção); `fallback > 0` → toast.warning (algumas fotos não passaram o gate D-02); `ok > 0` → toast.success (canonical OK em todas as 6 ou subset); `ok===0 && fallback===0 && disabled===0` → toast.warning 'Nenhuma foto canonicalizada (ver logs)' (edge case nunca-deve-ocorrer dado o endpoint shape, mas defesa explícita).
- **Badge variant logic three-way:** plan specified two-way (default/secondary based on fallback); SUMMARY agrega que disabled também triggera secondary porque kill-switch indica que canonical não rodou pra essa reading — visualmente igual a fallback para founder (ambos = não usou canonical). violet-600 reservado para "tudo OK" sinal explícito.
- **Canonical signed URLs TTL=24h:** explicitly NOT D-T6 600s (que vale para Modal pipeline downstream). Plan 07.1-03 admin photos endpoint TTL=24h é founder download convention; canonical_url herda mesma TTL pra simetria. Plan explicitly noted no Task 3 action: "TTL=24h (existing convention)".
- **Canonical sign error non-fatal:** se `createSignedUrls` falhar no batch canonical (storage timeout, etc.), `canSignError` é logged e `canonicalUrlByIndex` permanece vazio — todos os `canonical_url` no response caem para null. Originais já foram signed, response 200 preservado. Defense: NUNCA invalidar o response inteiro por falha no augmenter step (canonical_url é opcional para o consumer).
