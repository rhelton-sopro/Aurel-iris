### Novas decisões desta sessão

#### D-01: Trust gate — fallback comportamento
Quando o canonical falha pra 1 foto de 6 (Sonnet bbox visualmente errada), **passa a imagem original ao Modal para essa foto específica** e marca `processing_metadata.canonical_status='fallback'` para essa imagem.

- Modal lida (mal, mas lida — evidência empírica 07.1.5: pipeline não crasha em close-up, só produz detect/segment ruim).
- Terapeuta não vê fricção; UX preserva liveness.
- 5 fotos canonical + 1 raw é um delivered reading válido (degraded mas não fail).
- `canonical_status` é audit-able pelo founder via `/admin/calibration`.

**Rejeitado:** "block + ask for retake" (frustra terapeuta sem ganho clínico claro), "hard fail reading" (UAT-killer pro dogfooding), "founder admin quarantine" (adiciona fila de trabalho manual).

#### D-02: Trust gate — mecanismo de detecção
Combo **cross-angle consistency + geometric sanity**. Pre-Modal (server-side em apps/web). Não muda Modal contract.

- **(A) Geometric sanity** — bbox center deve estar nos centrais 60% do frame (cada coord in [0.20, 0.80]) E radius_pct in [0.05, 0.30]. Catches edge cases tipo "bbox no canto" ou "radius=0.40 cobrindo metade do rosto".
- **(B) Cross-angle consistency** — para cada olho, calcular median(center_x), median(center_y) entre os 3 ângulos. Se um ângulo está >0.08 do médian em x OU em y, flag esse ângulo como outlier. Cobre o failure mode "right_frontal mislocated com conf 0.78" (smoking gun do re-probe).

Trigger: gate falha → `canonical_status='fallback'` → original ao Modal pra essa foto.

**Rejeitado:** geometric-only (não pega right_frontal — center 0.45,0.45 tava dentro do range), Modal post-check (exige retroactive flagging + Modal-side mudança), confidence threshold standalone (right_frontal era conf 0.78).

#### D-03: Trust gate — retry policy
**Sem retry.** Gate falhou → fallback direto.

- Mantém latência canônica ~$0.05/reading + ~5s (parallel) ou ~18s (sequential — planner decide).
- Se 1/6 vira 2/6+ após rollout, retry com prompt rephrasing ou Opus pode ser adicionado em phase de follow-up sem mudar contracts.

**Rejeitado:** retry com Sonnet rephrasing (+$0.008 + 3s + não testado), retry com Opus (5× caro + não testado), cascade (overkill pro caso que cai em fallback de qualquer jeito).

#### D-04: Rollout — feature flag default
**ON day 1** em produção via env var `CANONICAL_CAPTURE_ENABLED=true` (set via `vercel env`). Kill-switch: flip para `false` e redeploy → rollback em 1 commit + redeploy ao comportamento atual (raw → Modal direto).

- Todas as leituras NOVAS (pós-deploy) passam pelo canonical.
- Wave C (07.2) corpus tuning vê inputs consistentes desde dia 1.
- Founder dogfooding (≥3 leituras/semana × 4 semanas) valida o pipeline em produção.

**Rejeitado:** opt-in via admin (atrasa dogfooding canonical sem ganho de safety real), hard cutover sem flag (sem rollback rápido), per-reading flag permanente (overkill MVP).

#### D-05: Backfill estratégia
**On-demand via `/admin/calibration`.** Botão "Re-canonicalizar" por leitura. Sem batch script automático.

- Founder escolhe quais leituras existentes (~10-20 readings pre-07.1.6) valem o re-trabalho.
- Permite separar protocol issue (commit `f885462` capture protocol revisto) de canonical issue — founder decide o que reusar.
- Nailli antiga (`71a7bf1d`, pre-protocol) vs Nailli nova (`e85ea7de`, post-protocol) são readings separados; founder decide se quer canonicalizar a antiga pra audit ou descartá-la do corpus.
- Re-canonicalizar é idempotente: regenera o canonical crop, salva em `{therapist}/{reading}/canonical/{eye}_{angle}.jpg`, re-aciona Modal, mantém os originais inalterados.

**Rejeitado:** "never" (perde valor de re-anotar Nailli antiga), one-shot script (irreversível + força founder a aprovar tudo cego), status-gated (mesmo custo de script + lógica de exclusão sem ganho).

#### D-06: Regression suite
**Golden JSON + gated integration test.** Same pattern as Phase 7 `ANTHROPIC_INTEGRATION=1` (skip-by-default).

- Commitar `apps/web/scripts/output/landmarks-probe-sonnet-4-6.json` como fixture frozen (current 5/6 Nailli e85ea7de Sonnet output).
- Commitar `apps/web/scripts/probe-haiku-iris-landmarks.mjs` (currently gitignored) como reusable script.
- Criar `apps/web/lib/canonicalize/__tests__/probe-canonical.test.ts` gated por `CANONICAL_PROBE=1` env var. Re-runs Sonnet contra Nailli e85ea7de, compara bbox coords com tolerância (±5% center_x_pct e center_y_pct, ±10% radius_pct).
- Founder roda manualmente antes de PR em mudanças ao canonicalize endpoint ou ao prompt do Sonnet. CI não roda (custo Sonnet + flakiness VLM).

**Golden fixture set para 07.1.6 = Nailli `e85ea7de` only.** Corpus expansion é 07.2 Wave C.

**Rejeitado:** visual diff (precisa de dep `pixelmatch`/`ssim` + mais flaky com JPEG encoding), manual founder eyeball only (esquece de checar antes de mergear), probe sem teste (sem trigger automático de validação).

### Claude's Discretion (planner resolve)

- **Onde vive o canonicalize:** server-side em `apps/web` (não em Modal) — sugestão: novo endpoint `POST /api/capture/canonicalize` OR inline em `finalizeReadingAction` server action. Planner decide com base em testability + idempotência (re-call pra re-canonicalizar deve ser cheap path).
- **Storage convention:** `{therapistId}/{readingId}/canonical/{eye}_{angle}.jpg` paralelo a `originais/`. Mirror da convenção em `apps/web/lib/capture/storage-path.ts`. Nunca sobrescreve originais.
- **Schema additivo:**
  - `reading_images.canonical_storage_path text NULL` (column nova; NULL = não canonicalizada).
  - `vision_features.processing_metadata.canonical_status: {ok, fallback, disabled}` por imagem (jsonb, nested under `image_diagnostics[eye][angle]` ou similar — planner decide shape).
  - `vision_features.processing_metadata.canonical_sonnet_usage: {input_tokens, output_tokens, cost_usd}` agregado por reading (audit financeiro).
- **Parallel Sonnet calls:** 6 chamadas em paralelo via `Promise.all` (wall-clock ~3-5s vs ~18s sequential). Sem dependência entre bbox calls. Cuidar com Anthropic rate limits (Tier 1 RPM/TPM check).
- **Modal contract:** `process/route.ts` resolve signed URL — usa `canonical_storage_path` se non-NULL, senão `storage_path` (original). Modal pipeline inalterado.
- **`/admin/calibration` UI surface:** adicionar badge `canonical_status` (ok/fallback/disabled) por foto + botão "Re-canonicalizar" (D-05). Pequena extensão da página existente.
- **Probe script — make committable:** add header com runbook (env vars, expected output paths, cost expectation) + remove dependência de Nailli hardcoded (aceita reading_id como required positional arg; default mantido pra dev convenience).
- **Sharp resize quality:** planner escolhe interpolation kernel (`lanczos3` default, `mitchell` se quality issues). Output JPEG quality 92 (default sharp) ou 95 (preserve fiber detail).
- **Sonnet prompt:** reusa o prompt do probe script (`apps/web/scripts/probe-haiku-iris-landmarks.mjs` SYSTEM_PROMPT) como ponto de partida; planner refina se necessário (e.g., remover `eye_landmarks` se não usamos canthus). Token budget: ~1.8k input / ~170 output per call (current probe).
- **Anthropic SDK reuse:** `apps/web/lib/anthropic/client.ts` é Phase 7 server-only client com `Anthropic` instance + `MODEL` constant. Canonicalize precisa de instance separada (modelo diferente — Sonnet, não Haiku validate) ou parameteriza? Planner decide.
- **Test surface:** Wave 0 RED scaffolding pra sanity checks (`isCanonicalAccepted({bbox, frame_dims, peer_bboxes})` pure function) + Wave 1 endpoint implementation + Wave 2 integration (`finalizeReadingAction` wiring).

### Trust gate — threshold values empíricos
- **Geometric:** center coord in [0.20, 0.80], radius_pct in [0.05, 0.30]. Source: founder visual review de probe outputs.
- **Cross-angle:** outlier se >0.08 do mediano (em x OU em y) entre os 3 ângulos do mesmo olho. Source: empirical right_frontal failure delta = 0.10 from median; 0.08 catches it com folga.

### Sonnet pricing / cost envelope
- Sonnet 4.6: $3/MTok input, $15/MTok output.
- Probe atual: ~1.8k input + ~170 output per foto = $0.0079/foto.
- Per reading: 6 fotos × $0.0079 = $0.047 (~$0.05).
- Mensal MVP (50 readings/mês): ~$2.5. Fits envelope projetado em PROJECT.md (~US$ 100-150/mês total).

### Trust gate — failure mode atual (right_frontal)
- Center (0.45, 0.45), radius 0.13, conf 0.78 — todos dentro de range geométrico.
- Backlight center (0.52, 0.42), lateral (0.42, 0.45) — médian x = 0.45, mediano y = 0.45.
- Frontal x=0.45 OK, y=0.45 OK contra mediano... mas radius 0.13 vs backlight 0.17 vs lateral 0.13 — backlight é o outlier de radius mas isso é OK (backlight tipicamente diâmetro percebido maior).
- Founder marca right_frontal como visualmente errada mesmo dentro destes números → indica que a bbox em SI tá fora da íris (visualmente) mas os números estão dentro do range esperado.
- **Implicação:** cross-angle precisa ser por-feature (center_x E center_y separados), não combinada. Detection via `|center_x_pct - median_x| > 0.08 OR |center_y_pct - median_y| > 0.08`. Se nenhum trigger, e founder ainda vê errado, founder usa /admin Re-canonicalizar manualmente.
- **Aceito:** o gate D-02 talvez NÃO catch right_frontal específico (números estão consistentes); fallback via admin manual continua sendo escape hatch.
