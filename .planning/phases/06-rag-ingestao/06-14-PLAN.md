## RAG Ingestion (Phase 6)

Phase 6 indexes the founder's iridology library (18 PDFs/DOCX in `D:\Projetos\Iridologista\livros\`) into `knowledge_chunks` for retrieval by Phase 7's LLM analysis pipeline.

### Quick reference

| Command | Purpose |
|---------|---------|
| `pnpm rag:ingest` | Full ingest of 16 unskipped books (~$3-9 with Contextual Retrieval, ~$0.20 without) |
| `pnpm rag:ingest --no-contextual` | Skip D-N1 Contextual Retrieval (cheap mode, ~$0.20 total) |
| `pnpm rag:ingest --dry-run` | Print chunk counts + cost estimates without API calls |
| `pnpm rag:ingest --book "<source_book>"` | Run a single book (use canonical book key from `books_manifest.json`) |
| `pnpm rag:ingest --limit-chunks 50` | Smoke-test mode (process first 50 chunks total, then stop) |
| `pnpm rag:purge --book "<source_book>"` | DELETE all chunks for one book (D-I2 — re-ingestion procedure) |
| `pnpm rag:spot-check` | Run 3 hardcoded scenarios + print top-5 chunks for qualitative review |
| `pnpm audit:vocabulary:db` | Scan `metadata.tags_livres` in DB for forbidden LGPD vocab |

### Required environment variables

| Variable | Purpose | Source |
|----------|---------|--------|
| `VOYAGE_API_KEY` | Embedding (voyage-3) + reranking (voyage-rerank-2.5) | https://dash.voyageai.com/api-keys |
| `ANTHROPIC_API_KEY` | D-N1 Contextual Retrieval (Haiku 4.5 + prompt caching) | https://console.anthropic.com/settings/keys |
| `SUPABASE_URL` | Database URL | Supabase project settings |
| `SUPABASE_SERVICE_ROLE_KEY` | Service-role for INSERT (bypasses RLS) | Supabase project settings (KEEP SECRET — `.env.local` only) |

### Cost guards

- **D-G1: Voyage embedding hardcap = US$ 5.** Script aborts (exit code 2) if running cost crosses $5. Alerts at $1/$2/$3/$4. Idempotency means re-running picks up where it left off (already-indexed chunks via `content_hash` UNIQUE skip the API call).
- **D-N1: Contextual Retrieval hardcap = US$ 15** (separate from voyage hardcap). Abort behavior identical.
- **Cost reconciliation:** the script's reported total is computed from Voyage's `total_tokens` response field (authoritative billing metric). Compare with https://dash.voyageai.com/billing — should match within ~5%.
- **If hardcap aborted:** review logs to identify which book caused the burn. To raise the cap permanently, edit `HARDCAP_USD` in `vision-service/scripts/lib/budget.py` (`VoyageBudgetGuard` or `ContextualBudgetGuard`). To raise temporarily, run with `--book "X"` to process specific books only.

### Re-ingestion procedure (D-I2)

When a book's chunking strategy changes or content extraction was wrong:

```bash
# 1. Purge the existing rows
pnpm rag:purge --book "Bernard Jensen Iridology Simplified"

# 2. Re-ingest with current chunker + extractor
pnpm rag:ingest --book "Bernard Jensen Iridology Simplified"

# 3. Verify new chunks
psql "$DATABASE_URL" -c "select count(*) from knowledge_chunks where source_book = 'Bernard Jensen Iridology Simplified'"
```

### Post-ingest tagging (D-T1)

The ingest script writes chunks with EMPTY metadata arrays:
```json
{
  "constituicao_referenciada": [],
  "setores_referenciados": [],
  "sinais_referenciados": [],
  "dimensoes": [],
  "tags_livres": []
}
```

Vocabulary tagging (D-T2..T5 controlled vocabularies + D-T6 dúvida → null/[] strictness) happens in a SEPARATE Claude Code session — NOT inside `ingest_knowledge.py`. The founder + Claude pair walk through chunks in batches, applying the vocabularies in `vision-service/scripts/data/vocabularies.json` and the canonical sinais in `vision-service/data/jensen-reference.md`. The output is a JSONL file of `{chunk_id, metadata_updates}` that gets applied via a small SQL UPDATE batch.

This is by design (D-T1):
- Reproduzibilidade is not a priority (biblioteca não escala)
- Sessão Claude Code (Sonnet 4.6/4.7) supports founder validation in real-time
- Custo zero adicional além da assinatura

The tagging update script is out of scope for Phase 6 v1; founder runs ad-hoc SQL UPDATEs after each batch.

### Troubleshooting

**`VOYAGE_API_KEY is not set`:** Set in `.env.local` (NOT `.env` — that's git-tracked) and `source` it before running. Or `export VOYAGE_API_KEY=...` per-shell.

**`SUPABASE_SERVICE_ROLE_KEY appears malformed (no eyJ prefix)`:** The key is wrong — service-role JWTs always start with `eyJ`. You may have copied the anon key instead. Get the right one from Supabase Dashboard → Settings → API → `service_role` (warning: never commit this).

**`HARD CAP REACHED` after 30 min:** Re-run is idempotent — `pnpm rag:ingest` again will skip already-indexed chunks. If you exhausted the cap before finishing a single book, that book is too long for $5; raise the cap in `budget.py` or use `--no-contextual` to halve the cost.

**`voyage embed failed after 3 retries`:** Voyage API was down or rate-limited. Re-run; idempotency handles it.

**Spot-check returns weird chunks for an obvious query:** Likely the `alta_prioridade` flag in `books_manifest.json` is wrong — fewer or wrong books boosted. Edit manifest, then `pnpm rag:purge --book "X"` + `pnpm rag:ingest --book "X"` for affected books. Or adjust `ALTA_PRIORIDADE_BOOKS` in `apps/web/lib/rag/search.ts` (must match manifest).

**Latency p95 > 2s in production:** Check `hnsw.ef_search` in the RPC function — should be 100. If raised to 150-200, latency goes up but recall improves. Modify by re-applying the migration (it uses `create or replace function`).
