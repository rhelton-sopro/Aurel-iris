## Decision rationale: Print CSS over @react-pdf/renderer

Founder picked Print CSS during execution (asked via AskUserQuestion). Trade-offs:

| Approach | Deps | PDF Consistency | Server-side |
|---|---|---|---|
| Print CSS (chosen) | 0 new | Slight variance Chrome/Safari/Firefox | No (browser does it) |
| @react-pdf/renderer | +~1MB dep | Identical across browsers/OS | Yes |

Founder accepted the variance trade-off in exchange for zero infra additions. Implementation matches the spec criterion ("Exportar PDF generates clean continuous-text PDF") via browser's native Save-as-PDF print destination.

## What changed

### NEW Print Page Route

**`apps/web/app/(dashboard)/leituras/[id]/print/page.tsx`** (RSC):

- Same `dynamic = 'force-dynamic'` + `createClient()` session-bound + RLS pattern as `/leituras/[id]/page.tsx`
- Validates `(status === 'ready' || status === 'edited') && hasReport`; if not, `redirect(/leituras/[id])` → user lands on the appropriate State A/B UI instead of an empty print
- Composition top → bottom:
  1. **Screen-only banner** (`print:hidden`) with print instructions ("Use Ctrl+P (Windows) ou Cmd+P (Mac)") + "Voltar" link to `/leituras/[id]`
  2. **Print-included header**: "Iris Codex" wordmark (h1 font-serif text-2xl bold) + tagline "A íris como mapa do ser." (italic small muted) on a centered divider
  3. **`<ReportReadView>`** with NO `topActionsSlot` — no UI buttons in PDF
  4. **`<PrintTrigger>`** at end of DOM (auto-fires window.print after 250ms)
- `bg-white text-foreground` enforces correct color in print regardless of user's dark mode
- `min-h-screen` prevents layout collapse on short reports
- Print padding rules (`px-6 py-4 print:px-0 print:py-0`) let the browser's `@page margin` take over for paginated output

**`apps/web/app/(dashboard)/leituras/[id]/print/print-trigger.tsx`** ('use client'):

- `useEffect` → `setTimeout(() => window.print(), 250)` → cleanup on unmount
- 250ms delay lets the print-optimized layout fully render before the dialog opens (avoids flicker / partial-paint print)
- `try`/`catch` around `window.print()` — popup blockers / headless test environments don't crash; banner copy provides Ctrl+P fallback
- Returns `null` — pure side effect

## Judgment calls (1)

**Same-tab navigation for ExportPdfButton** (vs target="_blank" or window.open). Rationale: window.open() can be blocked by popup blockers; target="_blank" loses the "Voltar" navigation context. Same-tab + the print page's "Voltar" link is the cleanest UX. Trade-off: user briefly loses the original page state, but Next.js's router cache + RSC streaming makes the back-navigation fast.
