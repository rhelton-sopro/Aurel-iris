# Phase 7.4 — UI Design Contract (Iris Codex)

> Visual and interaction contract for Phase 7.4 (Iris Codex — relatório funcional
> adaptativo + add-on placeholder). Generated by gsd-ui-researcher.
>
> Phase 7.4 introduces:
> 1. `ReportAdaptiveView` — new adaptive renderer for `report_v2` jsonb (replaces
>    fixed-template 13-section editor for new readings).
> 2. `ReportAdaptiveEditor` — inline per-block editor for the same `report_v2` shape.
> 3. Renderer router — `/leituras/[id]` checks `report_version` and routes to
>    `ReportAdaptiveView` (2.0) OR `EditorAccordion` (1.0 legacy, untouched).
> 4. `AdvancedAnalysisCTA` placeholder + "Em breve V1.1" modal.
> 5. Rebrand "Aurel Iris" → "Iris Codex" across UI copy, manifest, emails.
> 6. Streaming progressive reveal — top-level keys appear in order as Sonnet emits.
>
> Phase 7's UI-SPEC (`07-UI-SPEC.md`) remains AUTHORITATIVE for the legacy fallback
> path (`report_version='1.0'`). This contract evolves the visual language; it does
> not regress it.

- **Sticky editor footer:** `h-16` (64px) — matches Phase 7 sticky footer pattern from legacy editor.
- **Inline editor textarea minimum height:** `min-h-[200px]` — matches Phase 7 D-U1 contract.

**Markdown rendering inside reports:** `react-markdown` + `remark-gfm` with Tailwind Typography prose plugin pattern `prose prose-sm prose-neutral max-w-none`. **DO NOT** introduce a third weight (700/bold) — `prose` defaults to 600 for `<strong>` which matches our semibold token.

**Grade label badge typography:** `text-xs` (12px) `font-medium` (500) inside Badge — Badge primitive defaults; do NOT override.

**Axis status badge typography:** `text-xs` `font-medium` — same.

**Priority focus numbering:** `text-base font-semibold` for the number (1, 2, 3) preceding each bullet, inline with the focus copy at `text-base`.

**Forbidden:** no third weight, no italics for emphasis (markdown `*emphasis*` renders as `<em>` inside prose — keep at semibold parity), no underline outside `<a>` links and hover states.

### Grade visual bar palette (PHASE-SCOPED EXCEPTION — clinical severity semantic)

The 5-segment horizontal grade bar is the ONLY chromatic exception in Phase 7.4. Palette uses Tailwind v4 default color tokens (NOT new project tokens — no addition to `globals.css`). Each segment fills left-to-right per grade. Empty (unfilled) segments use `bg-muted` (achromatic).

**Confirmed palette (founder discretion item D-UI4 — RESOLVED here, planner may re-confirm during plan-phase if founder objects):**

| Grade | tendency_label (recommended enum) | Filled segment token | Light value | Dark value |
|-------|-----------------------------------|----------------------|-------------|------------|
| 1 | `leve` | `bg-amber-200` | amber-200 | amber-300 |
| 2 | `leve-moderada` | `bg-amber-400` | amber-400 | amber-400 |
| 3 | `moderada` | `bg-orange-500` | orange-500 | orange-400 |
| 4 | `alta` | `bg-red-500` | red-500 | red-500 |
| 5 | `muito alta` | `bg-red-700` | red-700 | red-600 |

**Rationale for palette choice:**
- CONTEXT D-UI4 suggested `yellow-100 → red-700`. Refined to `amber → orange → red` because: (a) yellow-100 fails AA contrast on Card background (oklch 0.97); (b) amber-200 reads as "mild caution" without invoking traffic-light alarm; (c) preserves the perceptual jump from grade 3 → 4 where clinical attention should shift.
- Bar segments are 8px tall (`h-2`) — small enough that color saturation reads as semantic data, not visual loud emphasis.
- Bar is sibling to a textual `Grade {n}/5` Badge (text label of record) so colorblind users always have the explicit grade number; color is reinforcement, not the sole channel.

**Bar component structure:**
```
<div className="flex w-24 gap-0.5">
  {[1,2,3,4,5].map(i => (
    <div
      key={i}
      className={cn(
        "h-2 flex-1 rounded-sm",
        i <= grade ? GRADE_FILL[grade] : "bg-muted"
      )}
    />
  ))}
</div>
```

Where `GRADE_FILL` is the map above.

### `ReportAdaptiveEditor` — adaptive editor (NEW)

Mirrors `ReportAdaptiveView` layout, with two differences per block:
1. Each block-Card has a top-right `Editar` button (ghost variant) that toggles between read-only prose and edit form.
2. When expanded, the Card body replaces prose with form inputs; below the form, `Cancelar` (ghost) + `Salvar bloco` (default/accent) row.
3. Page-level sticky footer at bottom with global `Salvar alterações` + `Entregar ao cliente`.

```
│ ⚠ Audit banner (only if D-VOC3 hits present)                  │
├────────────────────────────────────────────────────────────────┤
│ ┌─ Card: Resumo executivo ───────────── [Editar]──────────┐   │

│ │ ... (same pattern)                                      │   │

│ {systems × N with same per-card edit pattern}                 │
│ {integrative_axes, bilateral_findings, etc.}                  │

│ │  during edit — modal still opens for visual consistency)│   │
│ └─────────────────────────────────────────────────────────┘   │
├────────────────────────────────────────────────────────────────┤
│ ┌─ Sticky footer (h-16, bottom-0, bg-background/95) ──────┐   │
│ │  [Salvar alterações] [Entregar ao cliente]   {n} editados│   │
│ └─────────────────────────────────────────────────────────┘   │
└────────────────────────────────────────────────────────────────┘
```

**Layout decisions (resolved from Claude's Discretion):**
- **Per-block edit toggle (not modal):** inline edit-in-place preserves visual context of where the block sits in the report; modal would obscure surrounding cards and break the visual rhythm.
- **Sticky global footer + per-block save coexist:** per-block save is the fast path (D-VAL2 diff computed per-key); global "Salvar alterações" is a safety net that batch-saves anything still in dirty state. "Entregar ao cliente" only ever lives in the sticky footer (one final commit gate).
- **Add-on CTA renders in editor:** for visual consistency between view and editor. Click still opens the modal (informational). Does NOT participate in dirty-state tracking.
- **Bilateral findings card in editor:** ALWAYS renders the edit form (checkbox + textarea), even when `asymmetry_present === false`, so terapeuta can toggle it on if they think the asymmetry was missed. Read view (`ReportAdaptiveView`) still omits the card entirely if false.

Unchanged. `EditorAccordion` at `/leituras/[id]` and `/leituras/[id]/editar` renders as it does today. No copy update beyond what is necessary to remove "Aurel" references (D-BR2) — those are NOT in the report renderer itself.

## Streaming Visual Cue (D-VAL3 — recommended path b: top-level keys in order)

Sonnet emits `report_v2` JSON with top-level keys in a FIXED order (set by prompt):

1. `executive_summary`
2. `constitutional_pattern`
3. `systems_with_tendency` (longest stream — multiple systems, each potentially long)
4. `integrative_axes`
5. `bilateral_findings`
6. `therapeutic_synthesis`
7. `priority_focus`
8. `clinical_note`

(Streaming key-detection parser counts each `"key_name":\s*("...|{...|[...]` match end on the accumulated buffer.)

### Streaming UI behavior

During stream:
- Hero card State B copy: `Gerando relatório… {N}/{TOTAL} blocos` where `TOTAL = 8` (the 8 top-level keys). `systems_with_tendency` array is counted as a single block here for progress purposes; UI shows "Sistemas com tendência" skeleton until the closing `]` of the array is detected.
- Progress bar fills `N / 8 × 100%`.
- Hint: "Você pode atualizar a página — o progresso fica salvo." (unchanged).
- BELOW the hero card, the report body area renders progressively:
  - For each completed top-level key: render its real Card.
  - For each pending top-level key: render a `Skeleton` block (`h-32 w-full rounded-lg`) with subtle `text-muted-foreground` overlay `Carregando…`.
  - For `systems_with_tendency` mid-stream: show a `Skeleton` until the array closes; once complete, render all systems at once (Sonnet emits the full sorted-and-graded array, so visual stability is preserved — no re-sorting jumps).
- StatusBadge in page header shows ephemeral client-side variant `Gerando…` (label only — no enum change). Variant: `secondary` with Lucide `Loader2 animate-spin` icon prefix, 14px.

On stream complete:
- Sonner toast: `Relatório gerado. Revise os blocos antes de entregar.`
- Hero card State C visible; report body now shows the full adaptive stack.

On stream error / disconnect:
- Hero card shows error state copy + `Tentar novamente` button (existing).
- Already-received keys remain in `report_v2` jsonb (incremental save same as Phase 7 D-S2 contract).
- On reload mid-stream: RSC reads current partial `report_v2`; if any keys present, render `ReportAdaptiveView` with the partial data + a subtle warning chip `Geração incompleta — {n}/8 blocos` and a `Continuar geração` outline CTA.

### Alternative (D-VAL3 path a — partial JSON parsing)

If founder + planner choose path (a) — incremental partial-JSON parsing via a library — the UI contract is identical at the block-completion granularity. Sub-block streaming (e.g. mid-sentence within a `clinical_description`) is NOT exposed to the UI in either path; per-block reveal is the visual unit of progress.
