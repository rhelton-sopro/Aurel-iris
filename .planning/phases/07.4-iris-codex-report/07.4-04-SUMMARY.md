# Phase 07.4 Plan 04: Tendency-engine placeholder Summary

Hand-crafted heuristic placeholder that translates Modal vision-pipeline `vision_features` into a `Tendency[]` for the Sonnet `<tendencies>` prompt block (D-PR2), shipping behind a barrel so Phase 7.5 swaps to a rules-based engine via a one-line change.

## What shipped

- **`apps/web/lib/tendency-engine/placeholder.ts`** (220 lines, `import 'server-only'`):
  - `mapVisionFeaturesToTendencies(features: IrisFeaturesForRag): Tendency[]` — pure function, no I/O, no DB.
  - 4 helpers: `safeArray<T>()` (jsonb coercion per MEMORY rule), `ring()` (rings.* present check), `sectorHasFinding(hour, types[])` (sector × finding-type traversal), `constitutionMatches(term)` (primary+secondary case-insensitive substring), `pushTendency()` (cumulative merge on duplicate system_id).
  - 8 hand-crafted rules across 7 systems: linfatico (2 — lymph_rosary + constitutional pattern), hepatico_biliar (2 — sector 8 + hematogênica constitution), digestivo (1 — sector 6/7), nervoso_autonomo (2 — nerve_ring + stress_rings), renal (1 — sector 4/5), imune (1 — derived from linfatico ≥3), musculoesqueletico (1 — sector 1/2).
  - 12 `TODO Phase 7.5 — replace with real engine` markers (one per rule body + 4 in the header docstring/comments for orientation).
  - Output sorted by `tendency_grade` desc so Sonnet sees highest-priority systems first.

- **`apps/web/lib/tendency-engine/index.ts`** (14 lines):
  - Barrel re-export: `export { mapVisionFeaturesToTendencies } from './placeholder'` with an inline `^^^^^^^^^^^ Phase 7.5 changes to './engine'` pointer comment.
  - Also re-exports the `Tendency` + `TendencyEngine` types from `./types` so callers only need one import path.

- **`apps/web/lib/tendency-engine/__tests__/placeholder.test.ts`** (124 lines, 7 tests, all GREEN):
  - lymph_rosary present → linfatico grade ≥ 3 with non-empty evidence
  - sector 7 lacuna → digestivo tendency with grade in [1,5]
  - empty features → returns `[]`
  - valid SYSTEM_IDS contract — every output member has a SYSTEM_IDS-enum system_id, integer grade in [1,5], non-empty rationale/system_name
  - source contains ≥ 6 `TODO Phase 7.5` markers (actual: 12)
  - maximal feature set yields ≥ 6 distinct system_ids (actual: 7)
  - barrel re-export resolves — `import { mapVisionFeaturesToTendencies } from '@/lib/tendency-engine'` is a function

## How it integrates

Phase 7.4-05 (route handler) calls `mapVisionFeaturesToTendencies(features)` and passes the result into `analyzeReadingV2({ tendencies, … })`. Phase 7.4-03's `analyze-v2.ts` already renders `<tendencies>` from this shape into the user prompt block (D-PR2).

Phase 7.5 will create `apps/web/lib/tendency-engine/engine.ts` with the identical export signature, then change exactly one line in `index.ts` from `./placeholder` to `./engine`. The 12 `TODO Phase 7.5` markers in placeholder.ts are the discovery index for what rules need replacement (`grep -n "TODO Phase 7.5" apps/web/lib/tendency-engine/placeholder.ts`).
