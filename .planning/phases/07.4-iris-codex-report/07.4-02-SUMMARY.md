## Decisions Made

- **Test asserts delta-counts vs baseline, not absolute clean.** The plan's acceptance criterion said "Run on current tree: `cd apps/web && node scripts/audit-vocabulary.mjs` exits 0 (baseline clean)" — but the current apps/web tree has 24 pre-existing hits (7 LGPD operational-comment `diagnóstico` in login/signup/capture, 17 iridological_jargon RAG metadata references to `Jensen` in lib/rag/* + lib/anthropic/analyze.ts + tests + AnalysisHero copy). These are Phase 3-7 debt and out of scope for Plan 07.4-02. Per project memory `feedback_quality_scoring_test_gate.md` precedent (Phase 3 test debt documented, doesn't gate ROADMAP), the test was structured to delta-check rather than gate on absolute clean. Future Plan 07.4-09 (rebrand) and/or a follow-up cleanup pass will address baseline.
- **`.test.mjs` → `.test.ts` rename.** Vitest config `include: ['**/*.{test,spec}.{ts,tsx}']` excludes `.mjs` files. The pre-existing `audit-vocabulary.test.mjs` stub (Wave 0 placeholder) was never actually picked up; its 4 `.todo()` cases never ran. Renamed to `.test.ts` so the test gate now executes (`pnpm test:run scripts/__tests__/audit-vocabulary.test.ts` → 7 passed).
- **Categorized stderr format `[category] (N hits):`.** Chosen so Plan 07.4-03 audit-v2.ts can mirror the same shape in `audit_metadata.iridological_jargon[]` / `audit_metadata.sopro_vocab[]` / `audit_metadata.forbidden_vocab[]` jsonb arrays. Single regex parser in the test reuses the same shape across both contexts.
- **`prompts/` added to DIRS in audit script.** The system.md file lives under `apps/web/prompts/` and must be scanned (with allowlist marker exempting it). This is what enables the audit to catch future regressions in the prompt file when someone removes the marker by accident.
