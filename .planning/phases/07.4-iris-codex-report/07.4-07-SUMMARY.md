## Decisions Made

- **Client/RSC split:** AdvancedAnalysisCTA (Dialog state) + AdaptiveAnalysisStream (Loader2 animation) + BlockEditPane + ReportAdaptiveEditor (useState/useTransition) need `'use client'`. VocabularyAuditBanner is purely declarative and stays RSC.
- **safeArray() over null-coalescing:** The MEMORY rule `feedback_safearray_jsonb_drift` says `?? []` doesn't catch wrong-type drift. Every iteration over `audit.iridological_jargon`, `audit.sopro_vocab`, `audit.forbidden_vocab`, `priority_focus`, `key_traits`, `systems_with_tendency`, `integrative_axes` is preceded by `safeArray<T>(value)` — including a test that asserts `iridological_jargon: 'not-an-array'` doesn't crash.
- **Locked-copy verbatim:** The 4 paragraphs in AdvancedAnalysisCTA were copied character-by-character from UI-SPEC §Surface 1c lines 241-244, including the em-dash in the button label. The test uses regex over the entire dialog text to catch any drift.
- **Plan 07b mount-point comment:** A 14-line comment block inside ReportAdaptiveEditor explains exactly where Plan 07b's SystemTendencyCardEditor + IntegrativeAxesEditor + BilateralFindingsEditor will mount. The 3 structured blocks render in VIEW mode today (using the same `SystemTendencyCard`, `IntegrativeAxisItem`, `BilateralFindingsCard` from Plan 06) so the editor is usable today, and 07b's PR diff cleanly shows the toggle-mode wrap.
- **Test-side Plan 07b absence assertion:** The ReportAdaptiveEditor test asserts `editar-systems_with_tendency`, `editar-integrative_axes`, `editar-bilateral_findings` testids are NOT in the document. This locks the scope contract — when 07b adds them, the test will fail and force an explicit assertion update.
- **TooltipTrigger render={<span />} pattern:** Reused from `AnalysisCTA.tsx` Phase 7 precedent — base-ui Tooltip.Trigger uses `render` prop, not Radix `asChild`. The plan's example code used `asChild` which is a no-op; corrected at implementation time.
- **JSON.stringify dirty-count:** The 5 simple blocks compare with direct `!==` (strings/objects), but the 3 structured blocks (systems_with_tendency, integrative_axes, bilateral_findings) need deep equality — using `JSON.stringify` across all 8 keys is uniform and lets Plan 07b edits flow into the counter without any code change in this file.
- **`isDelivered` short-circuit:** The editor renders a read-only message when `isDelivered=true`. This is defense-in-depth — the server actions also hard-gate on `is_delivered` (T-07.4-07-06 mitigated). The UI bypass via DevTools cannot mutate the DB.

**1. [Rule 1 — Bug] TooltipTrigger `asChild` prop doesn't exist on base-ui**
- **Found during:** Task 1 implementation of AdvancedAnalysisCTA
- **Issue:** The plan's action block at line 198-209 used `<TooltipTrigger asChild>` (Radix API). base-ui's `Tooltip.Trigger` uses `render={<span />}` instead — `asChild` would silently no-op and miss the tooltip wrapper.
- **Fix:** Adopted the `AnalysisCTA.tsx` Phase 7 precedent: `<TooltipTrigger render={<span />}>` wraps the Button so the tooltip can be triggered when the Button is disabled (disabled buttons block pointer events).
- **Files modified:** `apps/web/components/readings/AdvancedAnalysisCTA.tsx`
- **Commit:** `51fc50c`

**2. [Rule 2 — Critical UX] Stable test hooks via data-testid**

- **Files modified:** all 5 component files

**3. [Rule 2 — Defense-in-depth] Test for safeArray drift on jsonb**
- **Found during:** Task 1 test design for VocabularyAuditBanner
- **Issue:** The MEMORY rule says `??` doesn't catch wrong-type drift. The plan didn't ask for a drift test, but the rule's whole point is to catch this at the type boundary.
