## What changed

### NEW SECTION_TITLE_BY_NUMBER (types.ts)

Single source of truth for the 15 section display titles, keyed by heading-number string ('1', '2', '2.5', ..., '14') → display title (e.g. '2.5' → 'Sistemas em Bom Funcionamento'). ReportReadView consumes it; AnalysisStream + EditorAccordion still inline their own arrays (out of Plan 18 scope; future cleanup item).

### NEW ReportReadView.tsx (RSC continuous flowing surface)

Renders the 15-section Iris Codex report as a single professionally formatted document. Composition top → bottom:

1. **Header** — client name (h1 font-serif text-3xl bold) + reading date (LocalDateTime muted small) on a divider
2. **Optional topActionsSlot** — right-aligned action button row passed by parent (ReadingModeActions)
3. **Main body** — `max-w-prose mx-auto`. Iterates NUMBERED_SECTION_HEADINGS:
   - For each headingStr, get key via SECTION_KEY_BY_NUMBER and content from sections[key]
   - Skip if empty/missing (defensive — partial mid-stream + legacy 1.0 readings have fewer keys)
   - Strip leading `## §N — Title` heading line via STRIP_LEADING_HEADING_RE (mirrors EditorSectionItem pattern; handles §2.5 decimal)
   - Render `<section data-section-key data-section-heading>` with styled h2 `§{N} — {Title}` (font-serif text-2xl bold mt-12 mb-4; first one mt-8) + ReactMarkdown body in `prose font-serif leading-relaxed`
4. **Footer** — encerramento_disclaimer rendered as italic muted blockquote (border-l-4 pl-4) only if present

RSC by default — no 'use client'. ReactMarkdown is RSC-safe.

### NEW ReadingModeActions.tsx ('use client' island)

Top action button group passed via topActionsSlot. 3 buttons:

1. **Editar análise** — Link (button-styled outline + Pencil icon) to `/leituras/[id]/editar`. Existing accordion editor preserved verbatim there.
2. **Entregar ao cliente** — Button default + Send icon. Opens existing DeliverDialog → markReadingDelivered server action → toast + router.refresh.
3. **Regenerar análise (n/3)** — Button outline + RefreshCw icon. Gated by regenerationCount<3 + !isDelivered. Posts to `/api/readings/[id]/analyze` and drains the stream before router.refresh (no inline progress UI; page rerender picks up the new report). Tooltip when 3/3 explains the cap.

`isDelivered=true` short-circuits to a small status text "Entregue ao cliente em <date>" — all 3 buttons hidden. Therapist creates a new reading to regenerate after delivery.

Reuses existing markReadingDelivered server action + DeliverDialog component (zero changes there). Plan 19 will add a 4th button: Exportar PDF.
