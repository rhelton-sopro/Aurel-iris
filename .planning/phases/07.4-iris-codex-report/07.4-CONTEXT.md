## Phase Boundary

Sonnet 4.6 emite **um único relatório clínico-funcional adaptativo** por leitura, em formato JSON estruturado (não mais markdown freeform), consumido por um renderer adaptativo que organiza o relatório por **achados clínicos relevantes** (não por template fixo de seções anatômicas). Schema `report_v2` substitui `report_generated` da Fase 7 original. Sistemas sem achados relevantes são OMITIDOS do output (não preenchidos com "sem alterações" — relatório é adaptativo, não template).

Concretamente:

- **Schema redesign:** novo jsonb `readings.report_v2` substitui `readings.report_generated` para readings novos (post-deploy). Shape:
  ```json
  {
    "report_version": "2.0",
    "executive_summary": "string",
    "constitutional_pattern": { "description": "string", "key_traits": ["string"] },
    "systems_with_tendency": [
      {
        "system_id": "string (snake_case)",
        "system_name": "string (pt-BR display)",
        "tendency_grade": 1-5,
        "tendency_label": "string ('leve', 'moderada', 'alta', etc.)",
        "clinical_description": "string (prosa funcional, sem jargão iridológico)",
        "associated_manifestations": ["string"],
        "investigation_points": ["string"],
        "therapeutic_direction": "string (prosa curta acionável)"
      }
    ],
    "integrative_axes": [
      { "axis_name": "string", "status": "ativo|latente|inativo", "description": "string" }
    ],
    "bilateral_findings": {
      "asymmetry_present": boolean,
      "description": "string|null"
    },
    "therapeutic_synthesis": "string",
    "priority_focus": ["string", "string", "string"],
    "clinical_note": "string (disclaimer protetor + nota clínica)",
    "advanced_analysis": {
      "available": true,
      "generated": false,
      "credit_cost": 1
    }
  }
  ```
- **Prompt-mestre reescrito do zero** em `apps/web/prompts/system.md`. **D-PR1 frozen contract (Fase 7 CONTEXT) está SUSPENDED** — SPEC.md §6 ficou obsoleto pro V1 atual; founder ainda pode optar por re-sync SPEC pós-7.4 stabilization.
- **Structured output JSON mode**: Sonnet chamado via Anthropic JSON mode (`response_format: { type: "json_schema", schema: <reportV2Schema> }`). Server faz **zod validation** pós-stream contra o schema; falha → retry com prompt corretivo carregando o JSON inválido + zod error message; max 2 retries; 3ª falha → save raw + flag para founder review (não bloqueia leitura, mas marca para investigação).
- **Streaming progressivo**: parse parcial de JSON enquanto chega. Estratégia recomendada (planner decide entre): (a) `@anthropic-ai/sdk` `messages.stream()` em conjunto com `partial-json` ou similar para parse incremental do JSON; (b) Sonnet emite top-level keys em ordem fixa, parser detecta cada chave completa e renderiza section block.
- **Renderer adaptativo**: `apps/web/components/readings/ReportAdaptiveView.tsx` (novo) substitui `EditorAccordion.tsx` no rendering path do `report_v2`. EditorAccordion continua existindo como **legacy renderer para `report_version='1.0'`** (25 readings existentes).

## Implementation Decisions

### Schema redesign — D-SCH*

- **D-SCH1 (`readings.report_v2 jsonb` novo, NÃO sobrescreve `report_generated`):** migration `0013_iris_codex_report` faz:
  ```sql
  ALTER TABLE readings
    ADD COLUMN report_v2 jsonb,
    ADD COLUMN report_v2_delivered jsonb,
    ADD COLUMN report_v2_edit_diff jsonb DEFAULT '{}',
    ADD COLUMN report_v2_generated_at timestamptz,
    ADD COLUMN report_v2_delivered_at timestamptz,
    ADD COLUMN report_version text DEFAULT '2.0' NOT NULL;

  -- Backfill: existing readings (com report_generated populated) ficam como legacy 1.0
  UPDATE readings SET report_version = '1.0' WHERE report_generated IS NOT NULL;

  -- New table for add-on family (V1.1+)
  CREATE TABLE reading_addons (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    reading_id uuid NOT NULL REFERENCES readings(id) ON DELETE CASCADE,
    addon_type text NOT NULL CHECK (addon_type IN (
      'iridological_deep', 'client_facing', 'therapeutic_plan',
      'longitudinal_comparison', 'nutritional_map', 'exam_recommendations'
    )),
    generated_content jsonb,
    generated_at timestamptz,
    credit_cost int NOT NULL DEFAULT 1,
    model_version text,
    therapist_id uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
    created_at timestamptz DEFAULT now()
  );
  CREATE INDEX idx_reading_addons_reading_id ON reading_addons(reading_id);
  CREATE INDEX idx_reading_addons_therapist_id ON reading_addons(therapist_id);

  -- RLS: therapist sees only own
  ALTER TABLE reading_addons ENABLE ROW LEVEL SECURITY;
  CREATE POLICY reading_addons_therapist_select ON reading_addons FOR SELECT USING (therapist_id = auth.uid());
  CREATE POLICY reading_addons_therapist_insert ON reading_addons FOR INSERT WITH CHECK (therapist_id = auth.uid());
  ```
  **Não dropa** `report_generated`/`report_delivered`/`audit_metadata`/`report_generated_at` — continua hospedando legacy `report_version='1.0'`. Drop é polish pós-V1.1 quando todos legacy readings forem migrados ou arquivados.

- **D-SCH2 (Drop GENERATED column `ai_report_raw` + função `jsonb_concat_sections_pt_br()`):** Estes eram artefatos de D-P1 (Fase 7) para manter contrato LLM-04 retro-compat. **LLM-04 contract revogado** (texto concatenado não faz sentido pra report adaptativo variável; PDF entrega via Fase 8 vai usar `report_v2` direto). Migration 0013 inclui:
  ```sql
  ALTER TABLE readings DROP COLUMN ai_report_raw;
  ALTER TABLE readings DROP COLUMN ai_report_edited;
  DROP FUNCTION IF EXISTS jsonb_concat_sections_pt_br(jsonb);
  ```
  **Risk check:** grep code para `ai_report_raw|ai_report_edited` references antes de migration apply; planner verifica. Esperado: zero callers em web app (UI consome `report_generated` jsonb diretamente).

- **D-SCH3 (`report_v2_edit_diff` per-system-id, não per-section-number):** shape `{ system_id: { delta_type: 'adicionado'|'removido'|'corrigido'|'reescrito', char_delta: int, levenshtein_pct: float }, executive_summary: {...}, therapeutic_synthesis: {...}, ... }`. Chaves: cada `system_id` em `systems_with_tendency[]` + top-level keys editáveis (executive_summary, therapeutic_synthesis, priority_focus, clinical_note). Phase 10 telemetry contract redesign de Phase 10 reusa ou reformata; **não é responsabilidade de 7.4 garantir Phase 10 compatibility forward**.

### Structured output + validation — D-VAL*

- **D-VAL1 (Anthropic JSON mode + zod schema):** chamada Sonnet:
  ```ts
  const reportV2Schema = z.object({ /* shape from D-SCH1 */ })
  const reportV2JsonSchema = zodToJsonSchema(reportV2Schema)

  const stream = await anthropic.messages.stream({
    model: 'claude-sonnet-4-6',
    response_format: { type: 'json_schema', json_schema: { name: 'report_v2', schema: reportV2JsonSchema } },
    system: systemPrompt,
    messages: [{ role: 'user', content: userPrompt }],
    max_tokens: 4096,
  })
  ```
  Post-stream: `const parsed = reportV2Schema.safeParse(JSON.parse(rawOutput))`. Falha → retry path.

- **D-VAL2 (Retry path on validation fail):** se `parsed.success === false`:
  ```ts
  // Retry 1: feed Sonnet o JSON inválido + zod errors
  const retryUserPrompt = `O JSON anterior falhou validação. Erros: ${JSON.stringify(parsed.error.format())}.
  Output anterior: ${rawOutput}.
  Por favor produza um JSON válido conforme schema acima.`
  ```
  Max 2 retries (1ª + 2ª retry); 3ª falha → save raw output em `audit_metadata.invalid_json_output` + flag `audit_metadata.json_validation_failed=true` + render UI com "Erro de geração — founder review needed". Não bloqueia leitura.

- **D-VAL3 (Streaming + incremental render):** decisão entre 2 abordagens (planner pesquisa estado da arte 2026):
  - **(a) Partial JSON parsing**: lib `partial-json` ou `streaming-json-parser`. Parse incrementa enquanto stream flows; UI atualiza por key. Risco: lib maturity.
  - **(b) Top-level keys em ordem fixa**: prompt instrui Sonnet a emitir keys em ordem (`executive_summary` primeiro, então `constitutional_pattern`, etc.); parser detecta cada key completa via regex `"key_name":\s*"..."` ou `"key_name":\s*{...}`. Mais simples, sem nova dependência.
  - **Recommendation:** (b) primeiro (no new dep), (a) fallback se UX precisar finer-grain progress.
