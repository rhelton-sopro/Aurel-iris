### app/api/readings/[id]/pdf/route.tsx (new ~95 lines)

**GET handler**:
- `runtime: 'nodejs'` (PDF render needs Node primitives — pdfkit, fontkit, Buffer); `maxDuration: 60`
- Auth + RLS via `createClient` session-bound; `.maybeSingle()` → 404 on not-owned (mitigates T-PDF-01)
- Validates `(status === 'ready' || status === 'edited') && hasReport` — returns 409 JSON if not ready
- `reportToShow = reportDelivered ?? reportGenerated` (delivered preferred — therapist's edits are what client should receive)
- `renderToBuffer(<ReportDocument ... />)` returns Uint8Array
- Wrapped in `Response` with:
  - `Content-Type: application/pdf`
  - `Content-Disposition: attachment; filename="Leitura-{Name}-{Date}.pdf"`
  - `Cache-Control: no-store, max-age=0`
- try/catch: structured console.error log + 500 JSON `{ error: 'PDF render failed: <msg>' }` on render failure

**File extension is `.tsx`** (not `.ts`) because the route uses inline JSX `<ReportDocument ...>`. Next.js App Router accepts both extensions; `.tsx` is required for the JSX expression.

## Threat model

- **T-PDF-01** unauthorized download → mitigated by RLS + `.maybeSingle()` → 404
- **T-PDF-02** PII in PDF metadata (Document title includes client name) → accept (therapist owns this data; PDFs are user-driven downloads)
- **T-PDF-03** large reports timeout → accept (~16 sections × small markdown = fast render; maxDuration 60s ample)
- **T-PDF-04** markdown injection in PDF (e.g., reportDelivered tampered to embed JS-like content) → MITIGATED by render path: @react-pdf doesn't evaluate scripts; it accepts only Text/View nodes. Strip-inline regex drops backticks but doesn't escape — would render raw text. Acceptable trade-off for v1 (therapist owns the input via /editar)

## Judgment calls (2)

1. **`.tsx` extension for route file.** First draft was `route.ts` which produced 6 parse errors because `.ts` doesn't allow JSX. Renamed to `route.tsx`. Next.js App Router accepts both extensions. Recorded so future routes that render React trees server-side default to `.tsx`.

2. **Inline formatting stripped in PDF v1.** @react-pdf doesn't natively render markdown; would need a complex tokenizer to map `**bold**` to nested `<Text style={{fontFamily: 'Times-Bold'}}>`. v1 strips inline formatting (bold/italic/code) for simplicity — body still renders as paragraphs/bullets/numbered/blockquotes correctly. If founder wants inline bold/italic in PDF, follow-up plan can add a richer tokenizer.
