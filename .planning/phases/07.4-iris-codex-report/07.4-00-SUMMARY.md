## Decisions Made

- **Schema location**: `lib/anthropic/report-schema.ts` (not `lib/schemas/` or `app/actions/`) — co-locates with `analyze-v2.ts` consumer per established Phase 7 pattern (`types.ts ↔ analyze.ts` adjacency in original Phase 7).
- **`tendency-engine/types.ts` intentionally lacks `'server-only'`** — Tendency shape is consumable by tests and could be referenced by client display components (e.g., if a future analytics dashboard renders Tendency cards). `placeholder.ts` and `engine.ts` (7.5) carry `'server-only'` separately.
- **`expect.fail()` over `it.todo()`** for RED stubs — vitest treats `.todo()` as pending (test command exits 0), `expect.fail()` as failed (exits 1). Nyquist gate requires the test command to exit non-zero until the implementing plan ships, so `expect.fail()` is correct.
- **`REPORT_V2_TOP_LEVEL_KEYS` as exported const tuple** rather than inferred from `reportV2Schema.shape` — D-VAL3 path (b) streaming parser depends on stable insertion order; depending on `Object.keys()` iteration would be fragile across zod versions.
- **Fixtures use synthetic pt-BR clinical prose**, zero PII, zero forbidden vocab — planner reviewed during fixture creation per T-07.4-00-02 threat disposition.
