const GRAPH = 'https://graph.instagram.com/v23.0' // pinned; confirmar vXX.0 estável no changelog Meta

Tipo do valor armazenado (jsonb):
```typescript
interface StoredToken {
  access_token: string
  expires_at: string   // ISO
  obtained_at: string  // ISO
  last_refresh_at: string | null
}
```

Funções (todas async, server-only):

1. `getValidToken(): Promise<string | null>` — lê `app_settings` key `instagram_token` via `maybeSingle()`; retorna `access_token` ou `null` se ausente/inválido. NUNCA logar o token. Em catch, `console.error('[instagram-token] leitura falhou', err)` (sem o valor) e retorna `null`.

2. `refreshInstagramTokenIfNeeded(): Promise<{ refreshed: boolean; error?: string }>`:
   - lê o StoredToken; se ausente → `{ refreshed: false, error: 'sem token configurado' }`.
   - se `new Date(expires_at).getTime() - Date.now() > REFRESH_BUFFER_MS` → `{ refreshed: false }` (ainda longe).
   - senão: `GET ${GRAPH}/refresh_access_token?grant_type=ig_refresh_token&access_token=${current}` → resposta `{ access_token, expires_in }`. Calcular `expires_at = now + expires_in*1000`. Upsert o novo StoredToken (`last_refresh_at = now`). Retornar `{ refreshed: true }`. Em erro HTTP/parse → `{ refreshed: false, error }` (NÃO lançar; o cron daily faz `.catch`).

3. `instagramHealthCheck(): Promise<{ ok: boolean; error?: string }>`:
   - `const token = await getValidToken()`; se null → `{ ok: false, error: 'sem token' }`.
   - `GET ${GRAPH}/me?fields=id&access_token=${token}` → 200 com `id` → `{ ok: true }`; senão `{ ok: false, error: <code/message do Graph, SEM token> }`.

Usar `fetch` nativo (sem SDK). Redação: ao logar erros, NUNCA incluir `access_token` nem `INSTAGRAM_APP_SECRET`.
