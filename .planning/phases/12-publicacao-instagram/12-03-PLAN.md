Tipos de retorno:
```typescript
interface PublishResult { ok: boolean; mediaId?: string; permalink?: string; error?: string }
interface SweepResult { published: number; retried: number; failed: number; errors: number }
```

Funções:

1. `claimDue(service, limit)` — wrapper de `service.rpc('claim_due_social_posts', { p_limit: limit })` → retorna `SocialPost[]`. (Esta é a função que o teste do Plan 01 referencia.)

2. `publishDuePosts(): Promise<SweepResult>`:
   - `service = createServiceClient()`; primeiro `await service.rpc('reap_stuck_publishing')` (recupera presos).
   - `const claimed = await claimDue(service, SWEEP_CAP)`.
   - loop: `for (const post of claimed) { const r = await publishClaimed(service, post).catch(e => markError(service, post, e)); }` — agregar contadores.

3. `publishPost(id: string): Promise<PublishResult>`:
   - validar uuid (regex). `service.rpc('claim_one_social_post', { p_id: id })` → se 0 rows → `{ ok: false, error: 'não-publicável (já publicado ou em andamento)' }`.
   - senão `publishClaimed(service, row).catch(e => markError(...))`.

4. `publishClaimed(service, post): Promise<PublishResult>` — o núcleo:
   - `const token = await getValidToken()`; se null → throw `IgAuthError` (tratado como permanente-de-auth, NÃO erro de post — ver markError).
   - branch por `post.media.kind`:
     - `post`/imagem única: `POST ${GRAPH}/${IG_USER_ID}/media` body `image_url, caption, access_token` → containerId → `media_publish` `creation_id`.
     - `carrossel`: para cada slide (max 10) `POST .../media` `image_url, is_carousel_item=true` → childId; depois parent `media_type=CAROUSEL&children=<ids>&caption=<post.caption>`; depois `media_publish`.
     - `reel`: `POST .../media` `media_type=REELS, video_url, caption` → containerId; **poll** `GET ${GRAPH}/${containerId}?fields=status_code` a cada `REEL_POLL_INTERVAL_MS` até `FINISHED` (limite `REEL_POLL_MAX_MS`); `IN_PROGRESS`→continua; `ERROR`/`EXPIRED`→throw permanente; depois `media_publish`.
   - após `media_publish` → `mediaId`; `GET ${GRAPH}/${mediaId}?fields=id,permalink` → permalink.
   - gravar sucesso: `service.from('social_posts').update({ status:'publicado', ig_media_id, ig_permalink, ig_container_id, published_at: now, publish_error: null, updated_at: now }).eq('id', post.id)`.
   - retornar `{ ok: true, mediaId, permalink }`.

5. `markError(service, post, err): Promise<PublishResult>` — classifica (RESEARCH §"Retryable vs Permanent"):
   - extrair code do erro Graph. Se retryável (9007, code 4/rate, 5xx/network) E `post.publish_attempts < 3` → status volta a `'agendado'` (deixa pra próxima passada), `publish_error: <motivo>` (informativo), retornar `{ ok:false, retried:true }`.
   - se permanente (24, 2207xxx, reel ERROR/EXPIRED) OU `attempts >= 3` → status `'erro'`, `publish_error: <motivo>`. Retornar `{ ok:false }`.
   - se erro de AUTH (token null / code 190) → NÃO marcar erro de post; voltar status a `'agendado'` e logar `[instagram-publish] AUTH` (o health-check/notificação D-07 trata) — não queimar a tentativa indevidamente.
   - NUNCA logar token/secret.

Usar `fetch` nativo, host `graph.instagram.com` exclusivamente. Helper de erro `GraphError` carregando `code`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Node server-side → graph.instagram.com | container/poll/publish HTTPS com token |
| `media` (relative path no DB) → image_url/video_url enviado à Meta | superfície de URL que a Meta busca |
| Node server-side → social_posts (service-role) | atualização de status/resultado |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-08 | Spoofing/SSRF | image_url/video_url arbitrário entregue à Meta | mitigate | URL montada SÓ de `NEXT_PUBLIC_SITE_URL` + caminho relativo do DB; nunca aceitar URL absoluta externa em image_url/video_url |
| T-12-09 | Information Disclosure | token/secret em log de erro do Graph | mitigate | logar só code/message/status; nunca o access_token |
| T-12-10 | Tampering | publicar reel antes de FINISHED → post quebrado | mitigate | poll obrigatório `status_code` até FINISHED; ERROR/EXPIRED → erro, nunca publish |
| T-12-11 | Spoofing | host errado `graph.facebook.com` | mitigate | host pinado `graph.instagram.com/v23.0`; grep-gate == 0 |
| T-12-12 | Repudiation | falha some sem rastro | mitigate | `publish_error` gravado em toda falha; IGPUB-06 |
</threat_model>
