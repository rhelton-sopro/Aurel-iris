<objective>
Establish CPU-only CI for the vision-service Python pipeline. Without this, regressions in stage tests, Pydantic schema, jensen-map.json shape, or LGPD vocabulary would land silently. The workflow runs the same `pytest tests/` invocation that 05-01 bootstraps locally, plus the Python LGPD audit script (extended in 05-16) covering pipeline source + JSON assets + scripts.

This plan ships:

- `.github/workflows/vision-service-tests.yml` — single workflow, single job, two test steps (pytest + vocab audit), Python 3.11 matrix, `paths: 'vision-service/**'` filter so Next.js-only PRs don't trigger Python CI.
- Standard pytest GH Actions pattern from RESEARCH.md Validation Architecture (no Modal cloud, no GPU, no CUDA).
- Pinned action versions (`actions/checkout@v4`, `actions/setup-python@v5`) for supply-chain hygiene.

Honors D-X2 (CPU-only pytest in CI; Modal cloud test is manual smoke per 05-17), D-J2 (LGPD audit gates merge), and the cross-cutting cost envelope (CI = $0, no Modal billing during PRs).

Output: a pushed branch produces a green CI run on the next push to main / PR open.
</objective>

GitHub Actions standard pattern (RESEARCH.md Validation Architecture lines 1112-1143; PATTERNS.md "vision-service-tests.yml"):
- `actions/checkout@v4` checks out the repo HEAD.
- `actions/setup-python@v5` provisions Python with pip cache.

    2. Create `.github/workflows/vision-service-tests.yml` with EXACTLY this content (preserve indentation; YAML is whitespace-sensitive):

       ```yaml
       name: vision-service tests

       on:
         push:
           branches: [main]
           paths:
             - 'vision-service/**'
             - '.github/workflows/vision-service-tests.yml'
         pull_request:
           paths:
             - 'vision-service/**'
             - '.github/workflows/vision-service-tests.yml'

       # CI is read-only against the repo. No deploy, no token writes.
       permissions:
         contents: read

       jobs:
         pytest:
           name: pytest + LGPD vocab audit (Python 3.11, CPU-only)
           runs-on: ubuntu-latest
           strategy:
             matrix:
               python-version: ['3.11']
           defaults:
             run:
               working-directory: vision-service
           steps:
             - name: Checkout
               uses: actions/checkout@v4

             - name: Set up Python
               uses: actions/setup-python@v5
               with:
                 python-version: ${{ matrix.python-version }}
                 cache: pip
                 cache-dependency-path: vision-service/requirements.txt

             # CPU-only — no CUDA, no torch+cuda, no Modal cloud (D-X2).
             - name: Install dependencies
               run: |
                 python -m pip install --upgrade pip
                 pip install -r requirements.txt

             - name: Run pytest
               run: python -m pytest tests/ -v

             # LGPD audit runs even if pytest fails (catches both kinds of regression in one run).
             - name: LGPD vocabulary audit
               if: always()
               run: python scripts/audit_vocabulary.py
       ```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub-hosted runner → repo source | Read-only checkout via `permissions: contents: read`. |
| GitHub-hosted runner → pip / PyPI | Untrusted deps installed from `requirements.txt`; pinned versions are 05-01's responsibility. |
| GitHub-hosted runner → Modal Cloud | NO trust boundary established (workflow does not authenticate to Modal — D-X2). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-15-01 | Tampering | Compromised third-party action injects malicious code into CI | mitigate | Pin to major versions only on first-party Actions (`actions/checkout@v4`, `actions/setup-python@v5`); GitHub maintains these. No third-party Actions used in this workflow. Future hardening: pin to commit SHA. |
| T-05-15-02 | Privilege escalation | Workflow GITHUB_TOKEN abused for write operations | mitigate | Workflow-level `permissions: contents: read` strips all write scopes. Default tokens in 2024+ orgs are read-only by default; explicit declaration is defense-in-depth. |
| T-05-15-03 | Information disclosure | Test fixtures (consented iris JPEGs) leak via CI logs / artifacts | mitigate | pytest does not echo image bytes; `-v` flag shows only test names. No `actions/upload-artifact` step. Repo is private until LGPD review (PROJECT.md). |
| T-05-15-04 | Information disclosure | secrets.* values logged | mitigate | No `secrets.*` references in workflow. No Modal/Supabase tokens needed for CPU-only test. |
| T-05-15-05 | Tampering | Forbidden LGPD vocabulary lands in main without detection | mitigate | `audit_vocabulary.py` step with `if: always()` runs on every PR; non-zero exit fails the merge gate. Step runs even when pytest fails so vocab regressions are visible. |
| T-05-15-06 | Repudiation | Cannot tell which commit introduced a vocab regression | mitigate | `paths: '.github/workflows/vision-service-tests.yml'` triggers self-run on workflow edits; pytest verbose output identifies failing test by name; audit script prints `path:line: text`. |
| T-05-15-07 | DoS | Long-running CPU pytest exhausts free-tier minutes | accept | Phase 5 fixtures are small (~3-5 MB total per D-X4); pytest CPU run estimated <2 min. Free tier is 2000 min/month — well within envelope. |
